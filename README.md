# お小遣い家計簿 V3.2.8.5.12 — Galaxy / Android PWA 公開版

このリポジトリは「お小遣い家計簿 V3.2.8.5.12」のPWA公開用です。

公開サーバーへ置くのはアプリ本体だけで、実際の支出・残高・カード未払いなどのユーザーデータは端末内（IndexedDB / LocalStorage）に保存されます。

## 普段の使い方

ホーム画面 → お小遣い家計簿 → ＋支出

## 正式利用前の1件テスト

1. 100円のテスト支出を登録
2. 履歴へ出ることを確認
3. 分析へ反映されることを確認
4. テスト支出を削除
5. JSONバックアップが保存できることを確認

## 重要

- 実際の家計データやバックアップJSONはリポジトリへ追加しないでください。
- 更新前にはJSONバックアップを保存してください。
- Chromeのサイトデータ削除や端末初期化で端末内データが失われる可能性があります。


## V3.2.8.5.12 クレカ管理

- 楽天銀行・ゆうちょなどの銀行残高は管理しません。
- クレカ購入は支出と未払いに反映します。
- 財布・家の現金から実際に銀行へ補填した額は「クレカ用確保」として記録します。
- カード支払い時は未払いを減らし、確保済み分を消化します。
- 旧バージョンの銀行口座・履歴は移行時に非表示化して保持します。
- データモデル変更に伴い schemaVersion は 12 です。


## V3.2.8.5.12 履歴の編集・削除ルール

- 支出・資金移動・電子マネーチャージ・外部資金補填・手動のクレカ用確保・カード支払いは、整合性上問題がない場合に編集・削除できます。
- クレカ支出と同時に自動作成されたクレカ用確保、および確保資金返却は「連動」と表示し、直接編集・削除せず元の取引から変更します。
- 返金、残高調整、負債調整は直接の金額編集を行わず、必要に応じて削除後に再登録・再調整します。
- 手動のクレカ用確保は、必要額より多めの丸い金額でも登録できます。超過分は「今月のクレカ端数」として同じ月の次のクレカ利用に使います。
- 今月のクレカ端数は翌月1日に自動リセットし、銀行残高へ吸収されたものとして翌月には繰り越しません。未払いに対応している確保額はリセットしません。
- 既存V3.2.8.4.4以前のデータは破壊的変更せず、そのまま読み込みます。schemaVersionは12を維持します。


## V3.2.8.5.12 レシート撮影・OCR

- Galaxy / Android の支出入力画面から「レシートを撮影」または「画像を選ぶ」を利用できます。
- OCRはブラウザ内で Tesseract.js v5（日本語＋英語）を使います。OCRエンジン・WASM・言語データの読込にはCDN通信が必要ですが、レシート画像そのものをGitHubや家計簿データへ送信・保存しません。
- 撮影画像は長辺最大1,800pxへ縮小し、グレースケール・コントラスト補正してからOCRします。25MBを超える画像は拒否します。
- 読み取り候補：日付、店名、合計金額、支払方法、カテゴリ、商品名。結果は必ず確認・修正してから既存の支出フォームへ反映します。
- 「支出入力へ反映」だけでは取引は保存されません。最後に既存の「登録する」を押した時だけ saveTx() 経由で保存されます。
- 合計金額では「合計 / お支払額 / 領収金額」を優先し、「お預り / お釣り / ポイント / 税額」は支出額候補から除外します。
- 支払方法候補は VISA / Mastercard / JCB / AMEX / クレジット → クレジットカード、楽天Pay → 楽天Pay、PASMO / Suica / 交通系IC → PASMO、現金 / CASH → 財布です。
- 既存データは変更せず schemaVersion 12 を維持します。


## V3.2.8.5.12 OCR精度改善

- 縦長レシートでは文字幅が小さくなりすぎないよう、OCR用画像を最大約1,100px幅まで拡大しつつ、約550万画素・最大4,600pxに制限します。
- OCRは高コントラストのグレースケール画像と白黒二値化画像の2パターンで実行し、結果を重複除去して統合します。
- Tesseract.jsのページ分割を1回目は単一ブロック、2回目は疎なテキスト向けに切り替え、日本語レシートの縦長レイアウトに対応します。
- 合計金額は「合計・総合計・税込合計・お支払額・領収金額」を最優先し、楽天ペイ等の決済行を次点候補にします。
- ポイント、合計P、前回累計ポイント、取引ID、受付番号、カードNo、電話番号、税額、お預り、お釣りは合計候補から除外します。
- 「@99 2 198」のような単価・数量・行合計が次行に出る商品明細を解析します。
- CREATE / クリエイト表記を「クリエイト」として店名候補にします。
- 飲料商品が明細の6割以上を占める場合は「食費 ＞ 飲み物」を優先候補にします。スーパー名を認識した場合は複数商品レシートを「食費 ＞ スーパー・食材」として扱います。
- 2026-09-24のクリエイト型レシートを回帰テストに追加し、合計897円、楽天ペイ、飲み物カテゴリ、商品数量・合計、ポイント除外を検証します。
- schemaVersionは12のままで、既存取引データは変更しません。

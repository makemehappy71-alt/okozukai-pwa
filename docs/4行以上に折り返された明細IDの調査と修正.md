# 4行以上に折り返された明細IDの調査と修正（第19段階）

日付: 2026-11-07 / ブランチ: `codex/receipt-ocr-improvement`
基準: `7a8ad7179b1ad88e375608591861a403e1fde718`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで、4行以上の明細IDと値引帰属を再検証した。新しい実画像や実店舗の書式は検証していない。商品名・コード・価格の対応はテスト用で、商品辞書へ追加していない。

## 再現した問題

商品側・値引参照側とも、括弧と同じ認識元の完全なIDがそろい、一意に対応できても、基準版は「最大3行」の制限だけで保留にする。

```text
緑茶 (明細ID A
1
0
1)
2200083271771 1 ¥1,000
…
(明細ID A101) 値引 ¥100
```

この例は完全なA101が独立して印字される場合に限る。行数が増えたことを理由に、欠けた文字や記号を補うものではない。

## 修正と制限

3行という固定上限を、既存のID長上限16文字と各断片の条件に対応する上限へ変更した。
各ID断片は少なくとも1文字を持つため、16文字のIDは最大16行までである。探索はこの範囲で止め、途中断片・最終断片を追加した時点で16文字を超える場合も採用しない。17文字目を切り捨てたり、長い末尾断片を短縮したりしない。

復元には引き続き、次の条件を必要とする。

- `明細ID` と明記され、ラベルと値全体、または値部分が対応する1組の括弧で閉じる。
- 各行に英数字から始まるID断片があり、最後の断片と閉じ括弧が同じ行にある。文字・既存の記号をそのまま連ね、タブ・空行・別情報を読み飛ばさない。
- 同じ認識元に完全なIDが1行で独立して印字されている。商品側の折り返しには一意の完全な個別値引参照が、参照側の折り返しには一意の完全なIDを持つ商品名・数量・価格付き明細がある。
- 空白付きの別IDとの競合や重複がなく、実際の認識記録がある場合は、その記録内で根拠が成立する。
- 復元後も明細が一意であり、印字点数・小計・税額・値引・支払額の検証を通る。

継続記号がある場合もない場合も対象にする。既存の記号、大文字・小文字、O/0、I/1、先頭ゼロを訂正しない。
16文字までであっても、完全なIDがなければ復元しない。両側とも折り返されている場合や、完全な印字が別のOCRパスにしかない場合も、改行の意味を推定しない。

## 保留・原文・保存の保護

空白付きIDとの競合、ID内部の空白を消す必要がある場合、タブ・空行、価格・税・別情報の混入、不正な括弧、IDの重複、会計不足は自動確認・自動分割を止める。
会計後のフッターや学習辞書を完全なIDの代わりにせず、OCR間の割当矛盾も復元で解消したと扱わない。
元の正規化済みOCR原文と入力オブジェクトを保持し、解析用コピーだけで照合する。確認画面の照合案内と原文表示も維持する。
保存用の分割計画・取引・学習辞書に、IDや復元情報の新項目は追加しない。

追加回帰は、4・5・8・16行の商品IDと値引参照ID、各括弧、値部分の括弧、商品後のID、前後の参照、記号付きID、数字ID、全角、LF/CRLF/CR、単一値引、税配分、原文・入力オブジェクト保持を検証した。
完全なIDの欠落、両側の折り返し、空白付きIDとの競合、別パスだけの根拠、結合テキストによる根拠の捏造防止、タブ・空行・行末空白・別情報、16文字超過・末尾の切り捨て防止、括弧だけの継続行、不正な括弧、重複、会計不足、フッター・学習辞書の迂回も検証した。
模擬workerの3ケースで、商品側・参照側の条件付き復元とタブ付き継続行の保留、終了1回・保存書込0回を確認した。仮の既存取引・辞書・schemaVersion 12も維持した。

ブラウザには412pxの3ケースを追加した。

1. 商品側のA / 1 / 0 / 1とB / 1 / 0 / 2を完全な値引参照で照合し、値引100円/200円・支払900円/800円で分割する。
2. 値引参照側の4行IDを完全な商品IDで照合し、同じ結果で確認・分割する。
3. A101とA 101が両方読める場合は保留・警告とし、商品名を手入力しても分割計画を作らない。

照合案内と4行の折り返しを残す原文表示、保存用計画にIDを追加しないことも確認した。従来の360px・412px、各ID形式・値引・値下・税配分と実canvas画素一致も検証した。隔離ブラウザの仮の取引・辞書・IndexedDB/LocalStorageを保持した。OCRは模擬であり、実機性能測定ではない。

## 残存問題と保護範囲

- schemaVersion 12、app.js、保存処理・キー、学習辞書、Service Worker、公開バージョンを維持する。実データは開かず、仮データだけを使う。
- 指定作業ブランチだけへ反映し、mainと公開中のGitHub Pagesは変更しない。無関係なZIPとテスト成果物は対象外。
- 16文字を超えるID、17行以上、空行やタブを挟むもの、記号だけで始まる継続行、閉じ括弧だけの継続行は未対応。
- 完全なID・括弧・一意な対応が欠ける場合は手動確認を残す。文字・記号・空白の補完や削除はしない。
- 実画像の座標や印字の折り返し位置、実店舗の書式、ID認識率、Android実機の速度・カメラ・メモリ・操作性は未検証。

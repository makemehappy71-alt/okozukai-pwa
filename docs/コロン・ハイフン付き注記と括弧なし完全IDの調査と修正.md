# コロン・ハイフン付き注記と括弧なし完全IDの調査と修正（第40段階）

日付: 2026-11-08 / ブランチ: `codex/receipt-ocr-improvement`
基準: `24e606c5498587f0a58c62d591145ac80bd370bb`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで検証した。実画像・実店舗書式・Android実機からの再現ではない。テスト用の商品・コード・金額を学習辞書へ追加しない。

## 再現した問題

第39段階は、価格項目間の「商品／単品」と括弧なし完全IDの間に空白があってもなくても、固定語・明示ラベル・数字列で区切れる場合を扱っていた。一方、同じ境界に単一のコロンやハイフンがある入力は保留していた。


この例では、コロンは「商品」と明示されたIDラベルの間にあり、ID自体は先頭ゼロ付き数字だけである。同じ認識元の元の折り返し商品ID・注記ID・独立した完全な個別値引参照IDが印字まで一致し、単価500円・商品計1000円から数量2も厳密に確認できるが、基準版では採用できなかった。

`明細ID000200-単品` の場合も、数字列の後は固定した注記語であり、ID内部のハイフンや負の金額とは構文が異なる。`明細ID000200-01:商品` や、区切りの後に数字・通貨が続く場合はこの根拠を満たさない。

## 修正と安全条件

`receiptQuantityScopeMarker` の括弧なしID用の行全体に一致する2つの書式で、注記語とラベル付き完全IDの境界に、単一のASCII `:` または `-` を任意に認めた。境界の水平空白の有無は問わない。記号を一括削除する処理や、ID内のハイフンを取り除く処理は追加していない。

1. 商品/単品の固定語 → 境界記号0〜1個 → 明示された `明細ID` ラベル → 先頭ゼロ付き数字ID → 行末。
2. 明示された `明細ID` ラベル → 先頭ゼロ付き数字ID → 境界記号0〜1個 → 商品/単品の固定語 → 行末。

注記語自体の対応する括弧、水平空白、既存NFKCでASCIIへ変換される全角のコロン/ハイフン等を扱う。IDラベルと数字の間に以前から許可している任意のコロンとは別の位置なので、`商品:明細ID:000200` の各コロンは役割を分けて検証する。同じ境界の `::`、`--`、`:-` などは採用しない。

数値は正の値を示す先頭ゼロ付き連続数字2〜6桁だけで、ID内部のハイフン・負号・別の数字・文字修復は許容しない。NFKCでASCII `-` にならない数学のマイナス `−` やダッシュ `—`、未対応の区切り記号も推測で変換しない。`商品-000200` のように明示IDラベルがない場合や、追加の価格条件を含む場合も保留する。

第37〜39段階の次の条件は維持する。

- 対象は、先頭ゼロ付き数字IDが折り返された、数量の印字がない商品だけ。同じ認識元の元の折り返しID・注記ID・元から完全な独立した個別値引参照IDを、ゼロの桁数まで一致させる。
- 同じ正規化IDの元の完全な出現は、注記1件と独立した値引参照1件の計2件だけを必要とする。注記・商品・参照の重複を照合の補強にしない。復元結果や別の認識元・単独の注記画像からIDを借用しない。
- 注記は元の商品ID直後の単価・コード付き商品計の間に1行だけ。商品IDや値引参照との境界、別の注記・空行・価格行を読み飛ばさない。注記IDだけを値引額終端の証拠にしない。
- 元の10〜14桁の数字コード・明示された限定単価書式・金額上限を維持し、商品計÷単価が1〜99の整数で厳密一致するときだけ数量を検証する。印字数量を上書きせず、数量1の既定値・点数・総額・辞書から不足情報を補わない。
- 裸の値引額の局所的な円単位、IDと金額/数量/単価/コードの衝突、税・数量・会計・認識元間の矛盾、末尾の証拠が失われた場合の依存する前の判定の取り消しも維持する。
- 書き換えは解析用コピーだけ。原文のコロン/ハイフン・ID・ゼロ・空白・改行・価格順序と呼出元オブジェクトを保持し、一時根拠を保存しない。新しい保存項目やOCR呼び出しは追加しない。

今回の拡張は括弧なしIDに限定し、IDを括弧で囲む別書式へ境界記号を一般化していない。

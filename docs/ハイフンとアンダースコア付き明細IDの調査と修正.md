# ハイフンとアンダースコア付き明細IDの調査と修正（第14段階）

日付: 2026-11-07 / ブランチ: `codex/receipt-ocr-improvement`
基準: `fb6dbd84833c391f834a818f6de1208bcf29a6f1`

ハイフン・アンダースコアを含む明細IDと値引の帰属を、人工OCR文字列・模擬worker・隔離ブラウザの仮データで調査した。新しい実画像や実店舗の印字形式は検証していない。商品名・コード・価格の組合せはテスト用であり、商品辞書へ登録していない。

## 再現した問題

`A-101`、`A_101`、`101-1`等を「明細ID」と明記しても、基準版は記号をトークンとして抽出・保持しない。識別情報が無効となり、同一コード・数量・元価格の複数明細とその商品値引を照合できず、明細自体が残らないケースを再現した。
括弧付き、同一行、商品後、離れた明示参照でも同じ制約がある。

## 修正した範囲

### 明示されたIDの記号を保持

「明細ID」ラベルの値だけを対象とし、英数字の区間を1つの `-` または `_` でつなぐ形式を追加した。記号込みで2〜16文字、少なくとも数字を含むことを必要とする。既存の数字だけの番号と、記号のない英数字IDの条件は維持する。

```text
緑茶 (明細ID A-101)
2200083271771 1 ¥1,000

緑茶 (明細ID A_101)
2200083271771 1 ¥1,000

(明細ID A-101) 値引 ¥100
商品値引 ¥200 [明細ID A_101]
```

数字の区間だけからなる `101-1`、先頭ゼロがある `001-01` も、明示された構造付きIDとして文字列のまま保持する。これらを数値計算や価格・数量の推定に使わない。
異なる区切りを含む `A-1_B2` のようなIDも、各記号の間に英数字があり境界が明確な場合は、その文字列どおり照合する。

`A-101`・`A_101`・`A101` は別IDである。記号を削除・置換して照合せず、大文字・小文字、O/0、I/1、先頭ゼロの区別も維持する。
全角互換表記は従来のNFKCで正規化するが、マイナス記号やダッシュの類似字をASCIIハイフンへ修復しない。

### 不十分な根拠は保留

- 先頭・末尾の記号、連続する記号、記号の前後にあるID内部の空白は、短縮・結合して補完しない。
- `A--101`、`A-_101`、`A1 -01`等を、`A-101`や`A1-01`として使わない。ID直後の空白と記号を商品名側へ逃がして有効扱いすることも防ぐ。
- `/`等の未対応記号、類似ダッシュ、英字だけのID、長すぎるIDは確定対象に広げない。
- 「明細番号」「明細No.」は従来の数字専用のままにし、会員ID・取引ID・一般的なNo.から商品ごとのIDを推定しない。
- 参照先の記号が欠落・不一致の場合、重複ID、OCR間の割当矛盾、前後どちらの商品か不明な配置は自動確認・自動分割を止める。

値引の照合は既存の商品コード（コードなしなら商品名）・数量・元価格・明細ID・印字点数・小計・税額・支払額の一致を引き続き必要とする。IDだけで会計の不足を回避せず、学習辞書や商品名の確認だけでも帰属不足を解消したとは扱わない。
値引行の前後の明示参照、前置・同一行・商品直後の配置条件は第12・13段階の保護を引き継ぐ。
IDは解析中だけの情報であり、保存用の分割計画・取引・学習辞書へ新項目を追加しない。

ブラウザには412pxの3ケースを追加した。

1. 同じ行の `A-101` と `A_101` を区別し、前後の明示参照から値引100円/200円・支払900円/800円を分割計画に渡す。
2. 商品後の `A-101` と `A_101` について、商品値引と確認・分割の対応を維持する。
3. `A-101` に対する `A101` の参照は不一致として警告し、商品名を利用者が確認しても分割計画を作らない。

従来の360px・412px、各番号形式・値引・値下・税配分と実canvas画素一致も検証した。隔離ブラウザの仮の取引・辞書・IndexedDB/LocalStorageを保持し、保存用計画へIDを追加しないことも確認した。OCRは模擬である。

## 保護範囲と残存問題

- schemaVersion 12、app.js、保存処理・キー、学習辞書、Service Worker、公開バージョンを維持する。実データは開かず仮データだけを使う。
- 指定作業ブランチだけへ反映し、mainと公開中のGitHub Pagesは変更しない。無関係なZIPとテスト成果物はコミットしない。
- 未対応の記号、連続記号、英字だけのID、16文字を超えるID、ID内部の空白、欠落・誤読した記号は引き続き原本確認が必要。
- 商品とIDの境界や方向が不明な場合は手動確認を残す。記号・文字・番号を自動修復しない。
- 実店舗の印字形式、新しい実画像からのID認識率、Android実機の速度・カメラ・メモリ・操作性は未検証。

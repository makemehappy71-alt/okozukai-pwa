# 価格項目と値引参照の間の空行の調査と修正（第48段階）

日付: 2026-11-09 / ブランチ: `codex/receipt-ocr-improvement`
基準: `f56b3697e4133e4d1eddb3d717fbe7b7e967dfe4`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで再現した問題だけを対象とする。実画像・実店舗書式・Android実機での再現は未検証。テストの商品や金額を学習辞書へ追加しない。

## 再現と修正

第47段階は、2つ目の価格項目の直後に完全な値引参照を要求していた。次のように間に空行があると、同じ認識元の折り返し商品ID・単価・商品計・元の完全な参照で照合できても保留していた。

```text
緑茶 (明細ID 00
0100)
2200083271771 1 ¥1,000
(明細ID 000100) 値引
¥100
緑茶 (明細ID 00
0200)
単価 ¥500
2200083271771 ¥1,000

(明細ID 000200) 値引
¥200
小計 3点 ¥1700
合計 ¥1700
楽天ペイ ¥1700
```

次商品の数量は未印字だが、元のID印字がゼロの桁数まで一致し、単価500円と商品計1000円から数量2を確認できる。それでも直前の100円値引と次商品の200円値引の終端・帰属を確定できなかった。商品計先行、複数空行・タブ行、識別済み注記を挟む例でも再現した。

`receiptRecoverWrappedIds` で、2つ目の価格項目の後の書式行を走査し、最初の非空行の位置で既存の独立参照チェックを行う。裏付けが揃った場合だけ、解析用コピーの価格組から参照直前までを整理する。元の参照ID・ラベル・値引額のブロックは移動・補修しない。

## 安全条件

- 数量未印字の折り返された先頭ゼロ付き数字の商品IDと、元から完全に印字された独立した個別値引参照が、同じ認識元でゼロの桁数まで一致すること。復元結果・別の認識元・別画像領域からIDを借用しない。
- 越えるのは空文字または既存NFKC後の水平空白・タブだけ。最初の非空行が別ID・数量・商品・注記・価格・区切り線・制御文字なら停止する。後方の正しい参照を探して別項目を読み飛ばさない。
- 別行ラベル／金額を持つ参照は、既存の元の完全参照の開始位置と一致する必要がある。同一行に値引額を持つ参照も、ID印字・個別値引ラベル・金額を既存条件で照合する。
- 参照ID内部、参照IDとラベル、ラベルと値引額の間の空行は補完しない。値引額の後から次商品ID・小計までの終端判断は元の行のまま検証し、今回の走査を適用しない。
- 元のコード10〜14桁・明示単価書式・金額上限、商品計÷単価が1〜99の整数で厳密一致する条件、印字数量を上書きしない条件を維持する。既定数量1・点数・総額・辞書から不足を補わない。
- 価格組の間の書式行／完全ID付き注記、注記の出現数、重複商品・注記・参照、税・会計・認識元間の矛盾、裸の値引額の局所的な円単位と数量／単価／ID／コードとの値衝突チェックを維持する。
- 末尾の証拠が失われた場合は、依存する前の帰属確定も取り消す。原文・呼出元オブジェクトは保持し、一時的な解析位置・根拠を商品行・分割計画・学習辞書へ保存しない。

1・2・8・32・128行の書式行、単価先行・商品計先行、参照額の同一行／別行を確認する。新しい固定行数上限は設けず、元の購入領域を走査範囲とし、小計等を越えない。保存項目・OCR呼び出し・schemaVersionの変更はない。

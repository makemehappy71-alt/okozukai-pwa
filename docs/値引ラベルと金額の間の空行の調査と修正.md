# 値引ラベルと金額の間の空行の調査と修正（第50段階）

日付: 2026-11-09 / ブランチ: `codex/receipt-ocr-improvement`
基準: `008dac233ebfdf3c1a530a6d87903ab764b6e43b`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで再現した問題だけを対象とする。実画像・実店舗書式・Android実機での再現は未検証。テストの商品や金額を学習辞書へ追加しない。

## 再現と修正

第49段階は、ラベルの直後の行だけを金額として読んでいた。同じ認識元に2商品・3点・商品計各1000円・個別値引100円／200円・会計1700円がある人工レシートで、次のブロックの空行により直前の100円値引と次商品の200円値引の終端・帰属を確定できなかった。空行がない同じ入力は基準版で確定できた。

```text
緑茶 (明細ID 00
0200)
単価 ¥500
2200083271771 ¥1,000
(明細ID 000200) 値引

¥200
```

IDとラベルが同一行の例、元の完全IDだけが別行の例、価格順序の逆転、複数空行・タブ行、識別済み注記あり／なしでも再現した。

`receiptDiscountContinuation` に、金額の前の書式行だけを読む任意指定を追加した。有効にするのは、元の完全な先頭ゼロ付きIDを商品ID折り返しの根拠として読む場合だけ。通常の参照正規化や折り返された参照には有効にしない。

最初の非空行で既存の厳密な金額単独行を検証し、元の金額位置を参照の終端として保持する。書式行を越えたことを示す一時情報 `amountGap` がある参照を使う商品には、元の単価・商品計から数量を厳密に裏付ける追加検証を要求する。

## 安全条件

- 元から完全に印字され閉じ括弧を持つ、連続数字2〜6桁の先頭ゼロ付き参照IDと、折り返し商品IDが同じ認識元でゼロの桁数まで一致すること。ID内部を補修せず、別の認識元・画像領域・復元結果からIDを借用しない。
- 越えるのは空文字または既存NFKC後の水平空白・タブだけ。最初の非空行が数量・商品・注記・別ID・単価・区切り線・制御文字等なら停止する。後方の都合のよい金額を探さず、購入領域の終端を越えない。
- 既存の厳密な個別値引ラベルと金額書式・上限を維持する。数字だけの金額は既存の局所的な円単位・役割根拠を必要とし、ID／数量／単価／コードとの値衝突チェックを維持する。
- 金額候補が複数あれば、会計合計や差額で選ばない。即時の数値候補の重複チェックと、元の金額の後の境界判断を維持する。金額の後から次商品ID・小計までの空行を今回の走査で読み飛ばさない。
- 元のコード10〜14桁・限定した明示単価・商品計から数量1〜99の整数が厳密一致することが必須。印字数量・既定数量1・点数・総額・辞書から不足を補わない。印字数量のある商品の正規化へ広げない。
- ID内部・ラベル内部・スコープ語とラベルの境界の空行を補修しない。重複商品・注記・参照、税・会計・認識元間の矛盾を検証し、末尾の証拠が失われたときは依存する前の帰属確定も取り消す。

1・2・8・32・128行の書式行を確認し、元の購入領域を走査上限とする。原文の空行・タブ・先頭ゼロ・価格順序と呼出元オブジェクトは保持する。`amountGap`／`labelGap` と数量根拠は一時情報だけで、商品行・分割計画・学習辞書へ保存しない。保存項目・OCR呼び出し・schemaVersionの変更はない。

## 残存問題と保護

- ID・ラベル内部や別項目の混入、複数金額候補、金額の後の根拠不足、ID不一致・重複・矛盾は手動確認が必要。
- 保留時の未確定候補表示の品質問題は残る。未確認の適用を拒否し、名前を明示的に編集・確認した後も値引の自動分割計画を作らない条件を検証する。
- Android実機の速度・操作性、実画像の認識精度と店舗書式は未検証。ブラウザは模擬OCR・人工画像・新規コンテキスト・localhostと仮データだけを使用し、実データや実ブラウザプロファイルは開かない。
- 既存取引・IndexedDB・LocalStorageミラー・既存の学習辞書を保護する。schemaVersionは12を維持し、初期化・migrationは行わない。`app.js`、`sw.js`、`index.html`、`styles.css`、manifestに変更はない。
- mainは `e641912b6648757e39893659766b1de83dff8765`、Pages公開元は main `/` のlegacy構成。作業ブランチ以外の参照と公開設定は変更しない。

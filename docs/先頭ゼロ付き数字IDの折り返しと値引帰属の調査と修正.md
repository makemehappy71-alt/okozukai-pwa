# 先頭ゼロ付き数字IDの折り返しと値引帰属の調査と修正（第30段階）

## 再現した問題

完全な数字IDは既存仕様で `000100` から `100` に正規化する。一方、折り返し復元中の文字列は `000100` のままなので、参照の解析結果 `100` との比較で拒否していた。同じ認識元に元の表記が完全にある場合も復元しない。

```text
緑茶 (明細ID 000100)
2200083271771 1 ¥1,000
緑茶 (明細ID 000200)
2200083271771 1 ¥1,000
(明細ID 00
0100) 値引額（円）
100
(明細ID 00
0200) 値引額（円）
200
小計 2点 ¥1700
合計 ¥1700
楽天ペイ ¥1700
```

逆に、商品側の `(明細ID 00\n0100)` に対し、元の完全な `(明細ID 000100) 値引 ¥100` がある場合も同じ問題で復元できなかった。数値だけの一致からゼロの桁数を推定する修正は行わず、元の表記そのものを照合条件に追加した。

## 修正と安全条件

`receiptPrintedMarker` は、既存の正規化済み `id` に加え、照合に使う一時的な `printedValue` を返す。これはNFKC後の印字値で、先頭ゼロや内部空白を保持する。商品行や保存用計画の項目には追加しない。

`receiptRecoverWrappedIds` は、折り返し中の元の文字列と、検索用の正規化IDを区別して検査する。新しく復元できる先頭ゼロ付き数字IDには、次の条件を追加する。

- **値引参照のIDを復元する場合:** 同じ認識元に、元から価格付き商品として読める明細が1件だけあり、その商品名と同じ行に完全なIDが印字されている。そのIDの元の値が、連結した値 `000100` と一致する。`100`・`0100`・`00100` しかない場合、無関係な完全IDトークンしかない場合は認めない。
- **商品側のIDを復元する場合:** 同じ認識元の元の個別値引参照が正規化IDに対して1件だけあり、その完全な印字値が連結した値と一致する。既存の解析で個別値引ラベルと金額まで読める参照を必要とし、値引合計・販促・IDだけの行を根拠にしない。
- `000100` と `100` の商品が複数あるなど、正規化後のIDが重複する場合は保留する。復元候補の重複・復元後の商品行の一意性も正規化IDで検査する。
- `000 100` や `1 00` のように、空白の除去と数値正規化で同じIDになる別表記があれば保留する。空白を取り除いてIDを作る処理は追加しない。

数字IDは従来どおり1〜6桁の正の値だけで、全ゼロ・7桁以上を追加対象にしない。括弧一致、最大16文字・16断片の既存復元枠、ID断片中のタブ/空行/注記を読み飛ばさない条件、O/0等を補修しない条件も維持する。完全なID同士の既存の数値正規化は変更しない。

通貨表記付きの値引額は従来の処理を使う。数字だけの別行値引額は、元の商品に明示コード・数量・通貨付き価格が必要で、値が正規化IDや数量等と重なる場合は、その値引ラベルの `(円)` も必要とする。数字の終端・会計・認識元間の帰属の整合性も引き続き確認する。金額の先頭ゼロや誤読文字を補修する例外は追加しない。

原文のゼロ・括弧・注記・タブ・改行と呼出元オブジェクトを保持する。解析用コピーのIDも元のゼロ付き表記を残し、内部の商品IDや表示用IDは従来の数値正規化で `100` / `200` を使う。`printedValue` はマーカーの解析と照合だけに使い、商品行・保存用計画・取引・学習辞書へ保存しない。

## 残存条件と保護範囲

- 折り返した元のゼロ付き表記に一致する完全なIDが同じ認識元にない場合は手動確認を残す。数値として同じであることや合計だけから元のIDを推定しない。
- 商品と参照の両側が折り返されている場合、商品側の復元に必要な個別値引額も別行で相互推定になる場合は保留する。完全な印字を追加で確認できるまで自動確定しない。
- 重複ID・複数の復元候補・空白違い・会計不一致・認識元間の矛盾も保留する。
- 実店舗書式・画像からの認識率、Android実機のカメラ/速度/メモリ/操作性は未検証。
- app.js、保存処理・キー、schemaVersion 12、学習辞書、Service Worker、公開バージョンは変更しない。実ユーザーデータは開かない。
- 作業ブランチだけへ反映し、main・公開中のGitHub Pages・無関係なZIP・Git管理対象外のテスト成果物は変更対象外。

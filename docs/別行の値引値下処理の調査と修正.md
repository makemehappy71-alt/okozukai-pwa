# 別行の値引・値下処理の調査と修正（第8段階）

日付: 2026-11-06 / ブランチ: `codex/receipt-ocr-improvement`
基準: `f645fd51c2845e6e3ae48f341f2770229492e5a9`

第7段階で残した別行の値引・値下処理を、既存の解析コード・保存済み西友fixture・人工OCR文字列で再検証した。Android実機・実レシート画像による追加測定は行っていない。

## 再現した問題

| 入力 | 基準版の結果 |
| --- | --- |
| `テスト商品`の次行に`値引 ¥1,280` | 値引額の末尾280円を商品価格として取得する |
| `テスト商品 ¥2,500`の次行に`値引 ¥1,280` | 印字された元価格2500円を280円で置き換える |
| `値下(元 ¥2,500) ¥1,280` | 値下後価格の末尾280円だけを取得する |
| `値下 ¥1,280` / `特価 ¥1,280` | 280円を直前の商品へ割り当て、値下・特価ラベル自体も別商品として取得する |
| `値引後価格 ¥1,280` | 値引後価格を値引額1280円としても数え、二重に差し引く前提で会計を組み立てる |
| `値引 20%` | 税率ならぬ値引率の20を20円の値引額・商品価格として扱う |
| 元価格2500円の商品と100円の商品、値引1280円、小計1320円 | 値引前の価格が支払額を超えるため、明細選択・最終保護で商品を落とす |

金額の途中一致だけでなく、同じ関数が「値引額」と「値引後価格」を区別せず直前商品の価格にしていたことが原因だった。
後段の単品復元でも、値引・値下ラベルや価格の一部が商品名になり得た。

## 判定と修正

### 値引額

`値引 ¥1,280`、`割引額 ¥1,280`、`値下げ額 ¥1,280`、`クーポン割引 ¥-1,280`は値引額として扱う。
商品の価格に使わず、元の商品行に2500円が印字されていれば2500円を保持する。
単品について元価格2500円−値引1280円＝印字支払1220円が一致する場合は、既存の構造照合で元価格・値引額・支払額を保持する。商品名の確認条件は緩めない。
商品名と値引額しかない場合、元価格や値引後価格を新規に作らない。

`値引前価格`・`値引後価格`・`割引後金額`等を値引額として数えない。
率だけの20%から値引額を計算しない。ただし`値引 20% ¥500`のように円額自体が印字されていれば500円を読み取る。
次回クーポン等の既存の販促除外も維持する。

### 値下後価格

値下・値引後価格・割引後価格・特価・SALEのラベルに続く、通貨記号付きの完全な金額を値下後価格として読む。
明示された元価格付きの`値下(元 ¥2,500) ¥1,280`では、元2500円・値下後1280円・差額1220円を区別する。
隣接する商品名へ1280円を付け、値下・特価を商品名にしない。商品名が現在の店名と同じ場合も、店舗ヘッダーを商品として採用しない。

商品行に数量が印字されていれば保持し、値下後合計を数量で割り切れる場合だけ単価を得る。割り切れない場合は従来の単価未取得0とする。
明示された元価格と商品行の価格が矛盾する場合、元価格より値下後価格が高い場合、不正な桁区切り・余分な文字・複数金額・率しかない行は確定に使わない。
単品の小計復元や学習辞書の差額復元で、その不十分な値下根拠を迂回して確定しないようにした。

値下の元価格と差額は、解析中の明細に`markdownOriginalTotal`・`markdownDiscount`として保持する。同じ明細を複数OCRソースから統合しても、元価格が一致する場合だけ残す。
これは値下後価格への参考情報であり、レシート全体の値引額へ再加算しない。従来のクーポン用`originalTotal`等とは分け、学習時の価格も値下後価格のままにする。
保存形式・学習辞書形式は変更しない。

### 値引前の明細と全体会計

元価格の商品合計が支払額を超える場合でも、値引前合計−印字値引額＝印字小計、小計＋印字税額＝支払額が完全に整合する場合だけ、元価格の明細を保持する。
小計が欠ける場合や会計が一致しない場合は、従来の超過保護で拒否する。
複数商品への値引・税の配分は既存の按分を維持する。行が次にあるという位置だけで、値引全額を特定商品へ割り当てる変更はない。

西友の既存`値下(元 ¥139) ¥88C`は88円の商品明細を維持し、元価格139円と差額51円を参考情報として保持する。全体小計・税・店舗別処理は変えない。

## 保護範囲・残存問題

- schemaVersion 12、app.js、IndexedDB/LocalStorageの保存処理・キー、学習辞書、Service Worker、公開バージョンを維持する。
- 実データを開かず、Node VMと隔離ブラウザ内の仮データだけで検証した。
- 指定作業ブランチだけを更新し、mainと公開中のGitHub Pagesは変更しない。無関係なZIPは対象外。
- 商品名と値下後価格が隣接する、検証した形式が対象。商品コード・数量専用行等が間に入る形式、複数段の価格変更、未対応のラベル・ノイズ一般は解決していない。
- 元価格や値下後価格が読めない値引額だけの入力、率しかない入力、元価格が矛盾する入力は原本照合・手入力が必要。
- 複数の値引行の合算・商品への帰属判断は追加していない。複数商品への配分は従来の按分であり、特定商品の実際の値引額を断定するものではない。
- 参考の元価格・値下差額がOCR間で矛盾する場合、その参考情報を採用しない。
- Android実機のカメラ・速度・メモリ・操作性、実画像からの文字認識率は未検証。

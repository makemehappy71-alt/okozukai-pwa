# 同名同額商品の識別と値引帰属の調査と修正（第10段階）

日付: 2026-11-07 / ブランチ: `codex/receipt-ocr-improvement`
基準: `49ed2f8879090ffc566ed4a539a2222000e4a5a6`

実機なしで、同名・同額商品の抽出、OCR間の明細統合、値引の帰属を再検証した。人工OCR文字列と既存のコード形式を使用し、新しい実画像や店舗辞書は追加していない。
テスト中の緑茶とコード・価格の対応は仮の例であり、実店舗の商品対応を登録したものではない。

## 再現した問題

| 入力・経路 | 基準版の結果 |
| --- | --- |
| 同名・各1000円、異なる商品コード、商品値引100円/200円 | 値引合計300円は読めるが、コードを帰属判定に使わず確認保留になる |
| 同名・各1000円の2明細、片方だけに商品値引100円 | 単一値引の従来経路へ進み、両方に50円ずつ按分する。コードで区別できる場合も同じ |
| 同じコード・価格のコードだけの行が2回印字される | コードと価格だけの重複排除で1明細に減る |
| 店舗名の後にコードだけの行がある | 店舗名がその商品の名前として使われる場合がある |
| 統合OCRで2回目の同名商品名だけが削られ、別パスに名前付き明細が残る | 名前の類似度が足りず、同じコードの明細を別候補として残す。点数が過大となり明細が消える |
| 同じコード・金額で数量1と数量2があり、OCR間で順序が変わる | 数量1を数量2へ統合する場合がある。短い名前をより読める名前へ統合する後段でも数量差が消える |

## 識別と修正

### コード・価格・数量

異なるOCR元の明細は、既存の正規化後の商品コード・元価格・数量が一致する場合、名前が欠けていても照合できるようにした。
同じコードでも数量が違う場合は統合しない。後段の弱い商品名の統合でも、この条件を維持する。
同じOCR元にある別々の行を統合しない既存の保護は残す。

コード行の二重抽出防止は、「コード＋価格が以前出たか」から「その認識元内の同じ行を処理済みか」へ変更した。
商品名行と直後のコード価格行を両方処理しても1明細に保ち、別のコード価格行は同じコードでも保持する。
行を保持することと、それが別の実購入だと確定することは分ける。印字点数・小計・値引・支払額の照合は引き続き必要。
既知の店舗名と一致する文字列は、コードだけの商品の名前へ引き継がない。

### 値引の帰属

同じ認識元の「商品名→コード価格→商品値引」の対応を読み、コード・価格・数量で一意の商品を照合する。商品名はコードの直前に読めた場合だけ使い、コードや価格から新しい名前を作らない。
帰属結果を最終明細へ引き継ぐ際も商品コードを保持し、名前だけで同名商品を取り違えない。
コードがなくても、明示された数量・元価格・商品名で一意に対応し、会計が一致する場合は区別できる。

同名・同額の複数明細に値引が1件だけある場合も、帰属確認の経路へ進む。
コードで片方の商品に付く100円と確認できれば、その商品へ100円、もう片方へ0円を適用する。従来の50円ずつの按分には進めない。
一般的な会員値引・クーポン等の位置だけで商品を決めることはしない。

コードも数量も同じ明細は、明示的な商品値引が行順に並んでいても一意に識別できたとは扱わない。値引合計だけを保持し、商品別の自動分割・確認済みへの昇格を停止する。
コードが読めない認識元、OCR間で値引対応が矛盾する場合、商品名のないコードだけの明細、小計・点数・支払根拠が不足する場合も確定しない。

### 確認画面

同額のコード付き明細が複数ある場合、商品解析欄に読めた商品コードを表示する。利用者が原本と対応を確認するための表示であり、取引の保存形式へ新しい項目を追加しない。
商品名を便宜的に「商品A」「商品B」等へ書き換える処理は追加していない。

従来の360px・412px・混在税率・商品コード・値下・単一値引・複数値引の操作、canvas画素一致も合格した。
隔離したブラウザで既存IndexedDB/LocalStorageの取引不変と、確認後の既存辞書エントリ保持も検証した。OCR workerは模擬である。

## 保護範囲と残存問題

- schemaVersion 12、app.js、IndexedDB/LocalStorageの保存処理・キー、学習辞書、Service Worker、公開バージョンを維持する。
- 実データを開かず、仮データだけで検証した。mainと公開中のGitHub Pagesは更新せず、指定作業ブランチだけを変更する。無関係なZIPは対象外。
- 同じコード・数量・価格の商品が複数ある場合、物理的な購入単位の識別は未解決。明細の保持はできるが、行順だけで値引を確定しない。
- コードだけで読める商品名がない場合、候補は保持するが商品名・値引帰属を自動確定しない。
- コードの文字認識精度や新しいコード訂正・辞書対応は追加していない。今回の照合は既存のコード正規化後の一致を使う。
- 部分OCRしかない場合、数量・小計・点数が矛盾する場合、未対応の値引ラベルや離れた行の対応は引き続き原本確認が必要。
- 両候補で同じコードが読めても、商品名の揺れと数量差が同時にある場合、より読みやすい名前だけを根拠に数量を統合しない。コードと数量の両方が確認できないOCR間の一般的な対応は未解決。
- Android実機の速度・カメラ・メモリ・操作性、実画像からの認識率は未検証。

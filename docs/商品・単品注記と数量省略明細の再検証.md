## 調査結果と対応

数量の印字がない次商品で、単価と商品計の間に「商品」「単品」がある場合を再検証した。今回の対象では、修正対象となる誤った自動確定や、根拠が十分な入力を誤って保留する不具合は確認できなかった。アプリ本体を推測で修正せず、保留条件を維持し、専用回帰テスト・ブラウザ操作テスト・本記録を追加した。

次商品の明細・数量が確認できない以上、それを直前の別行値引額の終端証拠にして帰属を自動確定しない。元の完全ID、税額や支払総額が一致してもこの条件を維持する。

## 値引注記との区別

既存の `receiptDiscountScopeWord` / `receiptDiscountContinuation` は、元の完全な値引参照IDの後に「商品」「単品」と値引ラベル・金額が続く限定した配置を扱う。例えば、価格2項目が連続し、その後が次の順序なら、既存の個別値引の根拠として検証できる。

```text
単価 ¥500
2200083271771 ¥1,000
(明細ID 000200)
単品
値引額（円）
200
```

これは値引ラベルに付く明示された商品範囲であり、価格項目の間の注記とは配置・役割が異なる。同じ文字という理由で値引注記の処理を価格項目間へ流用しない。対照テストは、同じ語を価格項目間へ置けば保留、完全ID後の値引ラベルへ置けば既存条件で採用となることを確認する。追加の価格条件・壊れた括弧・ID違い・数量計算の不成立・会計矛盾を救済するものではない。

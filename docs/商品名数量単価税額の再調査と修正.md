# 商品名・数量・単価・税額の再調査と修正（第5段階）

日付: 2026-11-06 / ブランチ: `codex/receipt-ocr-improvement`
基準: `c1e73602b2de280b720706b624a234aad404f97a`

Android実機を使わず、既存の解析関数と保存済みテスト、追加した人工OCR文字列で原因を再現した。画像の文字認識率を改善したという結果ではなく、文字認識後の解析の修正である。

## 再現した問題と修正

| 対象 | 基準版で確認した問題 | 修正後 |
| --- | --- | --- |
| 商品名 | `24h 保湿クリーム`の24hが除去される。既存の名前品質判定では許容している接頭辞が、先の正規化で消える | 24h/24H/全角表記を保持。7UP等の既存の例外を維持 |
| 数量・単価 | `@100 2 250`を単価100・数量2・合計250として取得する | 明示された単価×数量と合計が一致しない記述は採用しない |
| 数量0 | `100 0 250`を数量0で取得し、`テスト商品 0 ¥100`は数量1として再解釈する | 数量0の明細を除外。単一商品復元・学習辞書の差額復元でも再生成しない |
| 単価の導出 | `テスト商品 3 ¥100`と商品コード付き明細で単価33円を作り、合計と矛盾する | 数量と合計は保持。割り切れる場合だけ単価を導出し、割り切れなければ既存の未取得表現である0を使う |
| 税額 | `外税 ¥1,250`や別行の`消費税額`の後の`8% 10点 ¥1,250`を1円として読む | 正しい3桁区切り全体を読む |
| コンパクト税額 | `小計 10点 ¥15,625`と`8Y 10点 ¥1,250`から印字税額を取得できない | 桁区切り対応。既存の点数一致・税率計算一致・通貨記号の条件は維持 |
| 税額の誤採用 | `消費税額 ¥1,25`を125円に変換する。税額見出しの後の商品価格を税額候補にする | 不正な桁区切りを拒否。別行から取得する対象を税率・点数・金額だけの形に限定 |

税額が読めないケースに推測した税額を追加する修正はない。コンパクト税額も実際に印字された値のみを採用する。
数量矛盾の判定では会計・ポイント・ヘッダーを除外する。`ポイント 0 ¥100`が既存の正当な学習辞書復元を妨げないことも検証した。
店舗固有の例外や辞書の追加は行わず、共通解析を修正した。

## 保護範囲・残存問題

- schemaVersion 12を維持。app.js、IndexedDB/LocalStorageの保存処理・キー、学習辞書、Service Worker、公開バージョンは変更しない。
- 実際の家計簿データを開かず、Node VMと隔離ブラウザ内の仮データで検証した。
- mainと公開中のGitHub Pagesは更新しない。変更対象は指定作業ブランチだけ。
- 明示された数量が0、または単価×数量と合計が矛盾する明細は、自動修復せず確認・手入力が必要。矛盾を含む入力では差額復元も抑止する。
- 合計を数量で割り切れない場合の実際の単価は特定できない。割引や混在単価等の理由を推測せず、単価未取得のまま数量と明細合計を保持する。
- 不正な桁区切りや、税額を特定できない自由な別行レイアウトは引き続き要確認。
- Android実機の速度、撮影画像での認識率、実機操作性は未検証。既存の不鮮明な商品名・画像起因の誤認識全般を解消したものではない。

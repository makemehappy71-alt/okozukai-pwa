# 性能改善とAndroid検証準備（第2段階）

日付: 2026-11-05 / ブランチ: `codex/receipt-ocr-improvement`
比較基準: 第1段階の `fd3d18a4138be0d3a1f13800047e0091914c064e`

Android端末は今回は接続できないとの回答に基づき、実機検証を未実施として維持した。
先にWindows上で負荷を測定し、確認できた組合せ探索と不要canvas生成を改善した。
main・GitHub Pagesの公開元・公開番号・schemaVersion 12・保存形式は変更しない。

## 確認した問題と修正

### 商品候補の組合せ探索

旧処理は18候補で262,143通りを検査し、毎回18行を走査していた。
同じ計測環境で、解のない18候補の例が約1.45秒かかることを確認した。

候補を最大9行ずつに分け、それぞれの部分集合を作り、金額の補数で結合する方式に変更した。
店舗辞書の加点・数量加点・品質評価・割引前優先・小計へのフォールバック・同点時の元の選択順を維持する。
整数金額かつ正確に加算できるスコアだけを高速処理の対象とし、小数などは元の探索へ戻す。
18候補の上限と、最初に全明細合計が一致する場合の即時採用も変更しない。

### 未使用canvasの事前生成

既知店舗・商品合計・支払方法が早期に確定していても、店名5領域・商品7領域・金額3領域・支払4領域をすべて生成していた。
1200×3600の模擬入力では、中間画像も含め33個のcanvasが生成されることを計測した。

任意の再OCR領域は、実際にその経路が実行されて`canvas`へアクセスした時に生成する。
生成済みの画像は同じオブジェクトを返す。画像解像度・切抜き座標・補正・認識モード・実行すべきOCR回数は維持する。
分割画像や全体画像は従来どおり準備する。

## 改善前後の計測

Windows x64 / Node v24.22.1 / Intel Core i7-8700、Node VM内。
各条件は初回ウォームアップを除いた5回の中央値。他のテストと同時実行せず測定した。
合計一致を調べる共通関数全体を測り、入力のマージ処理も時間に含めた。

| 商品候補数 | 基準版 | 改善後 |
| --- | ---: | ---: |
| 8 | 2.548 ms | 2.137 ms |
| 12 | 16.998 ms | 2.804 ms |
| 16 | 316.976 ms | 4.917 ms |
| 18 | 1449.975 ms | 6.367 ms |

これは特定の模擬候補に対するWindowsでの計測であり、Android実機や画像OCR全体の所要時間ではない。値は環境や実行ごとに変動する。

1200×3600の白色模擬画像、既知店舗・商品構造確定・支払方法既知の経路:

| 計測対象 | 基準版 | 改善後 |
| --- | ---: | ---: |
| 準備時に生成したcanvas数 | 33 | 8 |
| 生成canvasの画素数合計 | 108,089,184 | 22,940,400 |
| 画素数×4のRGBA換算 | 約432.4 MB | 約91.8 MB |
| 模擬workerの認識回数 | 4 | 4 |

RGBA換算は生成した表面の合計で、単位は10進MB。端末の実メモリ使用量やピークRAMの測定ではない。
描画領域の寸法と生成経路を記録する代替canvasで測定した。ネイティブ描画バッファ、worker、ImageData、GC等はこの換算に含めない。
全領域が必要なフォールバックでは、従来と同じ画像を順次生成する。

## Android実機で次に行う確認

実施場所は本番のGitHub Pagesと異なるoriginの検証環境とする。今回の452件合格を実機合格に読み替えない。
端末の接続・検証環境への到達方法は、実機を用意できる段階で設定する。

1. 端末機種、Android/ブラウザ版、アプリ実行形態（Chrome/PWA）、画面寸法、比較対象コミットを記録する。
2. 同じレシート画像を固定し、西友・ヤオコー・MEGA各店舗、短尺・長尺、8%/10%混在のケースを用意する。画像をリポジトリへ追加しない。
3. OCR準備が必要な初回1回と、エンジンデータ準備後3回を分けて、開始から確認画面までの秒数・認識回数・商品数を記録する。
4. 商品名・数量・単価・小計・税・支払額・店舗・カテゴリを原本と照合する。誤読を速度改善で隠さない。
5. カメラ縦横、影・長尺、撮り直し、商品部分の再読取り、キーボード表示中の確認・反映、戻る操作、連続読取りを確認する。
6. エンジン読込失敗→再試行、通信制限、バックグラウンド復帰、PWAの再起動を確認する。
7. 検証用の仮取引・辞書を事前に保存し、OCR処理だけでは取引が増えないこと、確認後の入力反映が既存取引を変更しないことを確認する。初期化・復元・本番キャッシュ解除は行わない。

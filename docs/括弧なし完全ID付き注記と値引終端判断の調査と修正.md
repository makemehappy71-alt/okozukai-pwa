# 括弧なし完全ID付き注記と値引終端判断の調査と修正（第38段階）

日付: 2026-11-08 / ブランチ: `codex/receipt-ocr-improvement`
基準: `af37db0f2e5ad863235720a2fee9867db5de374a`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで検証した。実画像・実店舗書式・Android実機からの再現ではない。テスト用の商品・コード・金額を学習辞書へ追加しない。

## 再現した問題

第37段階の価格項目間の範囲注記は、完全な明細IDが括弧で閉じられている場合に限定していた。次のようにIDに括弧がなくても、「商品／単品」とIDの間の水平空白、明示されたIDラベル、行末で区切れる場合まで保留していた。

```text

0100)

(明細ID 000100) 値引
¥100
緑茶 (明細ID 00
0200)

2200083271771 ¥1,000
(明細ID 000200) 値引
¥200
小計 3点 ¥1700
合計 ¥1700
楽天ペイ ¥1700
```

この例では、注記の完全IDは行末で終わり、同じ認識元の元の折り返し商品IDと、独立した完全な個別値引参照IDにゼロの桁数まで一致する。元の単価500円・商品計1000円から数量2を厳密に確認できる。IDが先に印字された `明細ID 000200 単品` も、数字と注記語を水平空白で区切れる。基準版では括弧必須の条件によってこれらを採用できなかった。

## 修正と安全条件

`receiptQuantityScopeMarker` に、行全体が次のどちらかに一致する場合だけ、括弧なしIDを読む条件を追加した。従来の括弧付きIDの処理は維持する。

1. 商品/単品の注記語 → 水平空白1文字以上 → `明細ID` ラベルと先頭ゼロ付き数字ID → 行末。
2. `明細ID` ラベルと先頭ゼロ付き数字ID → 水平空白1文字以上 → 商品/単品の注記語 → 行末。

注記語自体の対応する括弧、スペース・タブ、任意のコロン、既存NFKCによる全角表記を扱う。IDは連続した数字2〜6桁で先頭ゼロを必要とし、ラベルなし・異なるラベル・文字修復・ID内部空白/改行・0だけのIDを許容しない。IDラベルと数字は明示された構文で区切り、注記語と括弧なしIDとの間には必ず水平空白を要求する。

`商品明細ID000200` / `明細ID000200商品` のような語の連結、IDの長過ぎる数字列、別の数字・金額・条件文の混在、括弧の欠落/不一致、未知の制御文字を補修して採用しない。数字列を数量・単価・商品コード・値引額の代わりに使わない。

第37段階の次の条件はそのまま維持する。

- 先頭ゼロ付き数字IDが折り返された、数量の印字がない商品だけを対象とする。同じ認識元の元の折り返しID・注記ID・独立した元から完全な個別値引参照IDを、ゼロの桁数まで一致させる。
- 同じ正規化IDの元の完全な出現は、注記1件と独立した値引参照1件の計2件だけでなければならない。注記・商品・参照の重複を照合の補強にしない。復元結果や別の認識元、単独のID画像を借用しない。
- 注記は元の商品ID直後の単価・コード付き商品計の間に1行だけ。商品IDや値引参照との境界の行、別の数字・注記・価格行を読み飛ばさない。注記のIDだけを値引額終端の証拠にしない。
- 元の10〜14桁の数字コード・限定した明示単価書式・金額上限を維持し、商品計÷単価が1〜99の整数で厳密一致するときだけ数量を検証する。印字数量を上書きせず、既定の数量1・点数・総額・辞書から不足情報を補わない。
- IDと値引額・数量・単価・コードの数値が一致しても、別々の印字項目で役割を検証する。裸の値引額の局所的な円単位、税・数量・会計・認識元間の矛盾検査、末尾の証拠が失われた場合の依存する判定の取り消しも維持する。
- 書き換えは解析用コピーだけ。原文の注記・ID・ゼロ・空白・改行・価格順序と呼出元オブジェクトを保持し、一時根拠を商品行・取引・学習辞書へ保存しない。新たな保存項目やOCR呼び出しは追加しない。

## 残存条件と保護範囲

- 注記語と括弧なしIDの間に水平空白がない場合、IDの数字を一意に区切れない場合、IDだけの注記や追加の価格条件を含む場合は保留する。
- 元から完全な個別値引参照・価格/数量の独立した根拠が不足する場合や、重複・矛盾がある場合も手動確認を残す。IDなし注記の例外は追加していない。
- 実店舗の原画像・位置情報・認識率、Android実機のカメラ・速度・メモリ・操作性は未検証。性能同等性回帰は実機速度の測定ではない。
- app.js、保存処理・キー、schemaVersion 12、学習辞書、Service Worker、公開バージョンは変更しない。main・公開中のGitHub Pages・無関係なZIPは変更対象外。

# 括弧付き明細番号と英数字IDの値引帰属の調査と修正（第13段階）

日付: 2026-11-07 / ブランチ: `codex/receipt-ocr-improvement`
基準: `4ae92bb38a8cc0892bc9cb8b4b37d203761a0562`

括弧付きの明細番号、明示された英数字IDと値引の対応を調査した。人工OCR文字列・模擬worker・隔離ブラウザの仮データで再現しており、新しい実画像や実店舗の印字形式を検証したものではない。テストの商品名・コード・価格の対応は仮の例であり、辞書へ追加していない。

## 再現した問題

| 入力・経路 | 基準版の結果 |
| --- | --- |
| `(明細番号 101)`、`明細番号 (101)` | 番号として保持されず、値引先の識別に使えない |
| `緑茶 ¥1,000 (明細番号 101)` | 既存の同一行番号の分離に失敗し、正しい商品明細を残せない |
| `明細ID A101`、`緑茶 (明細ID A101)` | 数字限定の抽出・明細統合でIDが失われる |
| `A1O1`、`B1I1`等のID | 金額用の補正でO/I等を数字へ変更する経路があり、厳密なID照合に使えない |
| 値引行の前後にある括弧付き参照 | 商品の明示参照として扱えず、帰属が保留になる |

実装中の追加検証では、`緑茶 ((明細ID A101)` の余分な開き括弧を無視する抜けも再現した。対応する開閉括弧だけでなく、隣接する余分な括弧も検査し、保留にする回帰を追加した。

## 修正した識別条件

### ラベルとID

- 数字の番号は既存の `明細番号`、`明細No.`（ピリオド省略可）、`明細ID` を使い、1〜999999の整数に限定する。先頭ゼロは従来どおり数値として正規化する。
- 英数字は `明細ID` と明記された場合だけを対象とする。ASCII英字と数字を両方含む2〜16文字に限定し、IDそのものを文字列として保持する。
- 英数字IDの大文字・小文字、O/0、I/1、小文字l/1、先頭ゼロを区別する。`A1O1` と `A101`、`A101` と `a101`、`A001` と `A1` は別のIDである。
- 全角文字等はNFKCで正規化する。数字の補完、大文字への統一、金額用の誤読補正はIDに適用しない。
- `明細番号 1O1` 等を英数字へ解釈し直さない。会員ID・取引ID・一般的なNo.・ラベルのない括弧内の文字列も、商品ごとのIDへ昇格しない。

金額補正より前の文字列から識別子を読み、番号部分と商品名・価格・値引本文を分離する。明細をOCR間で統合する際も、検証したIDを文字列のまま保持する。

### 括弧と配置

対応する括弧は、1組の `(...)`、`[...]`、`【...】`（全角互換表記を含む）。ラベルと番号全体、または番号部分だけを囲む形式を対象とする。

```text
(明細番号 101)
緑茶
2200083271771 1 ¥1,000

明細ID [A101]
緑茶
2200083271771 1 ¥1,000

緑茶 (明細ID A101)
2200083271771 1 ¥1,000

緑茶 ¥1,000 (明細番号 101)
```

前置・同一行・商品直後の対応条件は第12段階を引き継ぐ。商品間で前後どちらへの対応か決まらない番号は、自動的に方向を決めない。
括弧の欠落・不一致、入れ子、複数ラベル、IDの途中にあるハイフン等は、都合のよいトークンへ短縮・修復せず確認保留にする。
通常の商品名の括弧、例えば `緑茶 (濃い味)` は保持する。正常な商品名の括弧と、その後に独立して印字されたIDの括弧も区別する。

### 値引の参照と保留

商品に直結した既存の商品値引に加え、次のようなラベル付きの明示参照を照合する。

```text
(明細ID A1O1) 値引 ¥100
商品値引 ¥200 [明細ID A101]
```

値引の前後どちらに参照があっても、商品側のIDと厳密に一致し、コード（コードなしなら商品名）・数量・元価格・点数・会計が整合する場合に限る。
単一の値引参照でも、ID中の数字を値引額として扱わず、実際の100円を対象明細だけに適用する。
括弧が壊れた単一参照を、一般的な値引按分へ戻して確定することも防止した。

重複ID、未知のID、大文字・小文字やO/0等の不一致、OCR間の割当矛盾、曖昧な配置、会計根拠の不足は自動確認・商品別の自動分割を停止する。学習辞書や商品名の利用者確認によって帰属不足を迂回しない。
番号・IDは解析中だけに保持し、保存用の分割計画や取引の形式へ新しい項目を追加しない。

ブラウザには412pxの3ケースを追加した。

1. 全角丸括弧と【】付きの番号101/102を表示し、値引100円/200円・支払900円/800円で分割する。
2. `A1O1` と `A101` を区別し、値引行の前後にある参照から同じ分割を行う。
3. `A1O1` に対する `a1O1` の参照は不一致として警告し、商品名を確認した後も分割計画を作らない。

従来の360px・412px、前置・同一行・商品後の番号、各値引・値下・税配分の操作と、実canvas画素一致も合格した。
隔離ブラウザの仮の取引・辞書・IndexedDB/LocalStorageの保持、保存用計画へIDを追加しないことも確認した。OCRは模擬であり、実機の認識率・性能測定ではない。

## 保護範囲と残存問題

- schemaVersion 12、app.js、保存処理・キー、学習辞書、Service Worker、公開バージョンを変更しない。実データは開かず、仮データだけを使う。
- 指定作業ブランチだけを更新し、mainと公開中のGitHub Pagesは変更しない。無関係なZIPとテスト成果物はコミットしない。
- ハイフン・アンダースコア等を含むID、英字だけのID、16文字を超える英数字ID、数字限定ラベルの英数字、未対応の括弧は識別対象に広げていない。
- OCRが大文字・小文字やO/0等を読み違えた場合は手動確認が必要で、自動修復しない。部分OCR・番号欠落・曖昧な配置も保留になる場合がある。
- 実店舗の印字形式、新しい実画像での番号認識率、Android実機の速度・カメラ・メモリ・操作性は未検証。

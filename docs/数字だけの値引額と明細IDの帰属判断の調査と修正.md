# 数字だけの値引額と明細IDの帰属判断の調査と修正（第27段階）

日付: 2026-11-08 / ブランチ: `codex/receipt-ocr-improvement`
基準: `6808eee6e757c455c219f0dfdc580010d55f498b`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで再検証した。実画像・実店舗書式・Android実機での再現ではない。商品名・コード・金額はテスト用で、学習辞書へ追加しない。

## 再現した問題と判断

基準版は、値引ラベルと別行にある金額に「¥」または「円」を必要とし、数字だけの行は保留する。同じ認識元に完全な商品IDと明示的なコード・数量・価格があり、「値引額」と印字され、他の数字の役割と区別できても復元しない。

```text
緑茶 (明細ID A101)
2200083271771 1 ¥1,000
…
(明細ID A101
) 値引額
100
```

数字だけでは、IDや合計が一致しても金額とは断定できない。そのため、数字だけの別行値を一般には解禁せず、以下の条件をすべて確認できる場合に限定した。従来の同じ行にラベルと金額がそろう処理や、通貨表記付き金額の条件は変更していない。

## 修正と安全条件

`receiptDiscountContinuation` は、独立した数字行について、金額を明示する「値引額」「割引額」「値下額」「値下げ額」のみを対象にする。「値引」「割引」「商品値引」だけでは新しい例外を認めない。前段の「商品」「単品」や括弧付きの同じ語は既存の限定条件内で扱う。
数字は1〜100000の正の整数を、前後のスペース・タブ以外を含まない形で必要とする。先頭ゼロ、符号、桁区切り、率、文字のOCR置換は行わない。全角の正規化は従来のNFKCを使う。

`receiptBareDiscountEvidence` で、以下を追加確認する。

- 同じ認識元の、商品名と同じ行に印字された完全なIDが対象を一意に示す。推定候補や、他の認識元の印字を根拠にしない。
- その直後に、数字10〜14桁のコード・明示された数量1〜99・通貨表記付き価格が1行で印字される。コードが解析された商品コードと文字列で一致し、数量・金額が一致し、既知の単価と数量の積が価格に一致する。数量省略時の既定値1や、コードの文字補修を根拠にしない。単価を整数で確認できない場合も保留する。
- 数字が、既知の各明細の数量・単価・価格・数字ID・コード、印字された点数、認識された明細の数量合計と重ならない。先頭ゼロ付きコードを数字として見た場合の一致も保留する。
- 同じ認識元に明示された商品コード・JAN・PLU・品番・数量・個数・点数・単価の値とも重ならない。価格の全額以上の値も新しい対象にしない。
- 数字の直後が次の明示的なID参照、既知の商品明細、または会計行への境界である。認識領域の切れ目や、未知の注記・単位が続く場合は終端を確定しない。

検証中に、数字の後ろに「個」「%」「対象外」が別行で続くと切り離して採用できる例を再現し、上記の後方境界確認を追加した。小計を含まない認識領域でも、数字が既知の数量合計と一致する場合に見逃さないことを検証した。

IDの括弧一致・16文字の上限、空白付きIDとの競合・重複、復元後の一意性、印字点数・小計・税・値引・支払額、認識結果間の整合性も引き続き検証する。別行の複数候補から金額を選ばず、空行・別商品・別ID・税・価格・注記を読み飛ばさない。
解析用コピーだけを既存の金額表記へ正規化し、元の正規化済みOCR原文に通貨記号を補記しない。原文の数字・注記・タブ・改行と呼出元オブジェクトを保持する。判断材料は一時的な内部情報であり、保存用計画・取引・学習辞書の項目は追加しない。

412pxのブラウザケースを7件追加した。

1. 折り返しIDと明示的な「額」ラベルの数字100/200を照合し、支払900円/800円で分割する。
2. 1行ID・独立注記・「額」ラベル・数字の形でも同じ結果で分割する。
3. 数字2が点数・既知の数量合計と重なる場合は、会計が一致しても分割を止める。
4. 数字100が既知の単価と重なる場合は、会計が一致しても分割を止める。
5. 数字100/200が先頭ゼロ付きコードと重なる場合は分割を止める。
6. A101とA 101が競合する場合は分割を止める。
7. 数字の次行に「個」が続く場合は分割を止める。

保留側では、商品名を手入力しても分割計画を作らないことを確認した。原文の数字・ラベル・改行、照合案内、保存用計画にIDを含めないこと、仮の取引・学習辞書・IndexedDB/LocalStorageの保持も確認した。従来の360px・412pxケースと実canvas画素一致も合格した。ブラウザは新規の隔離プロファイルとlocalhostを使い、OCRは模擬である。Android実機の性能測定ではない。

## 残存条件・保護範囲

- 「額」の明示がない別行の裸の数字、数量・単価・コード等と重なる数字、必要な商品情報の省略・不明瞭な印字、数字の終端が確認できない認識領域は手動確認を残す。IDや合計だけから役割を推定しない。
- 実際の値引額が単価・数量等と偶然同じ場合も、新しい自動採用条件では保留する。通貨表記付きや同じ行の値引表記は従来の処理を維持する。
- 複数の別行参照が同じIDを共有する場合、他の認識元にだけ根拠がある場合、ID競合・会計不一致も自動確定しない。
- 実画像の印字位置・店舗書式・認識率、Android実機の速度・カメラ・メモリ・操作性は未検証。
- app.js、schemaVersion 12、保存処理・キー、学習辞書、Service Worker、公開バージョンは変更しない。実データは開かず、仮データだけを使う。
- 指定作業ブランチだけへ反映する。main・公開中のGitHub Pages・無関係なZIP・Git管理対象外のテスト成果物は変更対象外。

# 数字だけの明細IDと値引額が一致する場合の調査と修正（第29段階）

日付: 2026-11-08 / ブランチ: `codex/receipt-ocr-improvement`
基準: `a7ef2c125a3ecac6a4c23eb939ee1723f2a6d055`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで検証した。実画像・実店舗書式・Android実機から得た再現ではない。テスト用の商品・コード・価格を学習辞書へ追加しない。

## 再現した問題

第28段階は「値引額（円）」で数量・単価・コードと金額を区別するが、数字IDとの一致は常に保留した。次の文字列でも、IDと金額の役割が印字で区別できるのに帰属を確定しない。

```text
緑茶 (明細ID 100)
2200083271771 1 ¥1,000
緑茶 (明細ID 200)
2200083271771 1 ¥1,000
(明細ID 100
) 値引額（円）
100
(明細ID 200
) 値引額（円）
200
小計 2点 ¥1700
合計 ¥1700
楽天ペイ ¥1700
```

原因は `receiptBareDiscountEvidence` の数字ID一致判定だけが、ラベル側の円単位を確認する前に無条件で拒否する位置にあったこと。数字IDに対応する商品と、値引額の印字を同じ認識元で一意に確認できても保留した。

## 修正と安全条件

数字IDとの値の一致も、第28段階の数量・単価・コードと同じ役割判定へ移した。今回のアプリ側の修正はこの条件の移動だけ。新しいID書式・金額書式・保存項目・店舗例外は追加しない。

- その値引参照の「値引額」「割引額」「値下額」「値下げ額」ラベルに、既存の限定書式 `(円)` が実際にある場合だけ、数字IDと金額を区別する。全角括弧は既存のNFKCで扱う。
- 同じ認識元に、商品名と同じ行の元の完全なIDと、その直後の明示コード・数量・通貨表記付き価格が必要。数量省略時の既定値、文字を補修したコード、不明な単価、折り返された商品ID同士の相互推定を証拠にしない。
- 元の完全なIDに対する商品が1件だけであること、復元した参照との一致、括弧・空白・記号・大小文字・重複の既存検査を維持する。値が同じ商品を対象に選ぶ処理は追加しない。
- 数字の前後を読み飛ばさず、直後が次の既知明細/ID参照または会計境界であることを確認する。認識領域の切れ目、別行の単位・条件、複数の数字候補は切り離さない。
- 点数・小計・税・値引・支払額・認識結果間の帰属が一致する場合だけ採用する。対象商品の全額以上の値引は保留する。

例えば、ID 100への200円値引とID 200への100円値引は、参照IDを根拠に200/100円へ割り当てる。金額と同じIDへ付け替えない。IDと金額が1/2で、数量や点数とも重なるケースも、各参照の円単位と完全な商品IDを確認した場合だけ区別する。

数字IDの先頭ゼロ除去は既存仕様を維持する。元の商品ID `000100` と参照 `100` が既存の数字ID正規化で対応する例を検証した。商品ID `100` と `000100` が同じ認識元に複数あると正規化後のIDが重複するため保留する。数字の補修やIDの前方一致を新たに認めない。

円単位がない場合、別の参照・共通見出し・別OCRパスにしか単位がない場合は従来どおり保留する。完全なIDが別の認識元にしかない場合、IDの競合・重複や会計不一致でも自動確定しない。元のOCR原文・呼出元オブジェクトを保持し、解析用コピー以外に通貨表記を補記しない。

## 残存条件と保護範囲

- 局所的な円単位・同じ認識元の元の完全ID・明示された商品情報・会計整合が不足する数字は、今回も手動確認を残す。値の一致や合計だけでは自動確定しない。
- 重複ID・複数の折り返し参照・認識結果間の矛盾は、別の追加根拠がない限り保留する。従来の復元書式・長さ・金額の範囲を拡張していない。
- 実店舗書式・画像からの認識率、Android実機のカメラ/速度/メモリ/操作性は未検証。
- app.js、保存処理・キー、schemaVersion 12、学習辞書、Service Worker、公開バージョンは変更しない。実ユーザーデータは開かない。
- 作業ブランチだけへ反映し、main・公開中のGitHub Pages・無関係なZIP・Git管理対象外のテスト成果物は変更対象外。

# 数量省略の次商品と値引終端判断の調査と修正（第33段階）

日付: 2026-11-08 / ブランチ: `codex/receipt-ocr-improvement`
基準: `e4149162d68b16afb19fe9bf8b0a9193061e3157`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで検証した。実画像・実店舗書式・Android実機からの再現ではない。テスト用の商品・コード・金額を学習辞書へ追加しない。

## 再現した問題

数量が省略されたコード価格行は、既存の商品抽出で数量1になる。第32段階はこれを終端の証拠に使わず、明示数量がない次商品を保留していた。元の印字に独立した単価があり、数量を一意に検証できる場合も対象外だった。

```text

0100)

(明細ID 000100) 値引
¥100
緑茶 (明細ID 00

単価 ¥500
(明細ID 000200) 値引
¥200
小計 3点 ¥1700

```

この例では、同じ認識元に商品計1000円・単価500円・完全な参照ID000200があり、数量2を独立に確認できる。数量1という既定値や、点数からの逆算は不要である。単価行が商品「単価」として抽出される問題も確認した。

完全な参照IDが単独行の場合、元の単価行が商品と誤認されてそのIDを持つことがあり、商品復元の候補と同じ物理的な参照の正規化候補が二重に数えられて保留になる例も再現した。

## 修正と安全条件

`receiptOmittedQuantityDetail` で、元の次商品に以下の連続した印字がある場合だけ数量の根拠を作る。

1. 先頭ゼロ付き数字IDの折り返しと商品名。
2. その直後の、数量を含まない数字コード10〜14桁・¥付きの商品計の行。
3. その直後の、明示的な単価の行。
4. その直後の、同じ商品の元から完全な個別値引参照ID。

単価は限定した `単価 ¥500`、`単価 500円`、任意コロン・横方向空白、既存の単価表記 `@500` / `@ ¥500` 等を対象とする。全角は既存のNFKCで扱う。裸の `単価 500`、単位だけの数字、税込等の追加条件、率、符号、誤認文字・非対応書式は推測しない。

商品計と単価は元の印字の正の整数を使い、商品計÷単価が1〜99の整数で厳密一致することを必要とする。商品計は10〜1000000、単価は1〜1000000の範囲に限定する。小数への丸め、数量1の既定値、印字点数・支払総額からの逆算は行わない。

この処理は、同じ認識元の元の完全IDとゼロの桁数まで一致する折り返し商品に限定する。個別値引参照の一意性・空白違い・正規化後の重複も検査する。単価と参照の間に別の単価・数量・注記・空行がある場合は読み飛ばさない。別の認識元や共通見出しの単価を借用しない。

条件を満たした解析用コピーだけに数量を補い、単価行を商品として数えないようにする。コード価格行の元の金額表記・円・税区分の印字は残す。数量・単価・商品計が新しい解析行と一致することを再確認し、その次商品を第32段階の独立した終端確認に使う。裸の別行値引額についても、元の単価と商品計の証拠を確認し、計算後の数量だけを証拠にしない。

付随する参照と、その同じ行範囲の単独の正規化候補は、同じ物理的な出現として扱う。別の行にある参照や商品を同一視する処理は追加しない。実際の重複ID・複数参照・会計不一致・認識元間の数量や帰属の矛盾は保留する。

点数・小計・税・値引・支払額の既存検査を維持し、根拠を取り消す場合は依存する前の判定も取り消す。数量が印字されていないだけで自動採用する条件には変更していない。

原文の数量省略・単価・ゼロ・括弧・改行と呼出元オブジェクトを保持する。数量は既存の解析用数量/単価項目へ反映し、根拠の一時情報は商品行・保存用計画・取引・学習辞書へ保存しない。保存用の分割計画は既存の金額形式のままで、新しい数量フィールドやschema変更を追加しない。

## 残存条件と保護範囲

- 元の完全なID、隣接したコード/商品計/明示単価/同じ個別値引参照の組が不足する場合は手動確認を残す。数量1の既定値や点数から不足情報を補わない。
- 単価が商品計と割り切れない、数量が1〜99の整数でない、単価の意味/価格基準が追加条件で不明、別パスの数量や帰属と矛盾する場合も保留する。
- 数量の印字が元からある行をこの処理で上書きせず、単価が先行する配置・離れた単価・未知の単価書式・英数字IDへ新しい例外を拡張していない。
- 実店舗書式・画像からの認識率、Android実機のカメラ/速度/メモリ/操作性は未検証。性能テストは同等性回帰で、実機速度の測定ではない。
- app.js、保存処理・キー、schemaVersion 12、学習辞書、Service Worker、公開バージョンは変更しない。実ユーザーデータは開かない。
- 作業ブランチだけへ反映し、main・公開中のGitHub Pages・無関係なZIP・Git管理対象外のテスト成果物は変更対象外。

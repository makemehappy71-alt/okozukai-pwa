# 残存OCR再調査と修正結果（第3段階）

日付: 2026-11-05 / ブランチ: `codex/receipt-ocr-improvement`
基準: `fb6e2cd0d6e87c07871ddc6bae6fa9013db542ad`

Android実機なしで再現できた共通処理だけを修正した。
比較用OCRテキストはテスト用の合成データと既存の保存済みfixtureを使用し、新しい実レシート画像は取得していない。
店舗の商品名・価格・税率を新たに推測する辞書追加は行っていない。

## 再現できた問題

| 入力/経路 | 基準版での問題 | 修正後 |
| --- | --- | --- |
| `牛乳 ¥238` / `緑茶 ¥100` / `豆腐 98` | 商品抽出0件。名前検証は2文字を許すのに、抽出正規表現は実質3文字以上を要求 | 2文字名をそのまま抽出する。1文字名・会計・メタ情報の除外は維持 |
| `テスト商品 ¥1,280` | 価格の桁区切りに非対応で抽出0件 | 税区分記号付き・同一行数量・次行数量を含め、1280円として抽出 |
| `2コX単1,280 ¥2,560` | 単価/合計が別の数字に分割され数量を失う | 数量2・単価1280円・合計2560円。座標による商品行判定にも適用 |
| `クーポン割引 ¥-1,250` | 値引額を1円と誤認し、2500円→1250円の明細を復元できない | 値引1250円として読み、元価格・割引・支払額を保持 |
| `生茶1000ml ¥100` / `チョコ110g ¥110` | 価格の数字を商品名の容量内からも削除し、`生茶 0ml` / `チョコ g`になる | 末尾の価格だけを取り除き、容量を保つ |
| `FANTA` / `LDC` / `ICE` / `EVIAN`で始まる再OCR商品名 | E/F/I/L等を無条件で落とし、`ANTA` / `サイダー` / `CE`等へ変わる | 単独で空白区切りになった行頭マーカーだけを除去 |
| `7UP 500ml ¥100` | 既に例外として意図されている7UPの数字が別の正規化で消える | 明示的な例外を数字除去にも適用し、7UPを保持 |
| `7ワッパーチーズセット` / `７ワッパーチーズセット`の複数OCR一致 | 先頭数字の不自然さを判定する前に再正規化で数字が消え、確認済み扱いになる | 半角・全角の先頭数字を保持して安全判定し、複数一致しても自動確定しない |
| `2コX単640,00 ¥1,280` | 不正な単価区切りを無視して数量確定。または数量行が商品名へ流れる | 正しい3桁区切りだけを処理し、残る不正区切り・数量記述行を商品として採らない |

桁区切りは数量・価格の記述内、または金額のキャプチャ部分で正規化する。商品名やrawName内の`1,000mg`などは変更しない。
括弧で明示された商品名のモデル番号も、末尾価格や数量として削らない。

## バーガーキングの残存例

既存の`E 【りのたかセト】 1 ¥1,090`が通常の商品抽出で残るようになった。
そのOCR断片を、既存の店舗別辞書が「ワッパーチーズセット」の候補へ結び付ける。

- 元価格1090円・割引250円・支払額840円を保持。
- `rawName`を残し、`lowConfidence=true`、`candidateOnly=true`、自動確定なし。
- OCRの商品名断片がなく、価格と割引だけの入力では「商品名要確認」を維持。

以前の「商品名要確認」を期待する既存テスト1件は、今回の商品行抽出改善に合わせて「辞書候補を表示するが確認必須」へ更新した。
会計・レビュー・辞書候補の根拠を追加テストでも検証した。価格一致だけで確認済み商品へ昇格する変更はない。

## テスト結果

| テスト群 | 合格数/件数 |
| --- | ---: |
| 既存家計簿 | 61/61 |
| 既存OCR | 337/337 |
| 第1段階の追加回帰 | 42/42 |
| 性能・画像領域の同等性回帰 | 9/9 |
| 今回追加したOCR回帰 | 46/46 |
| モバイル操作＋実canvas画像一致 | 3/3 |
| 合計 | **498/498** |

同じ新規46件を基準コミットに適用すると10/46件、修正後は46/46件。新しい商品名を推測せずに再現可能な36件の失敗を解消した。
既存OCRは前後とも337/337件。テスト名による保護対象の集計も、西友18/18・ヤオコー10/10・MEGA6/6のまま。

46件には正常系と、誤ったカンマ・不正な数量記述・メタ情報・価格しかない商品・不審な先頭数字を採用/確定しない負例を含む。
牛乳と緑茶の2明細について、商品別カテゴリと税按分後257円/108円、合計365円も確認した。

モバイル操作の412pxケースは、牛乳2点・税抜1280円・税102円・税込1382円のfixtureへ更新し、修正した抽出結果を実画面の確認操作まで通した。
360pxの従来ケース、実canvasの全OCR領域PNG一致も維持した。

## データと公開環境の保護

- schemaVersion 12、IndexedDB/LocalStorageのキー・保存処理・migration・学習辞書形式を変更しない。app.jsも変更していない。
- VMでは起動保存を止め、IndexedDB接続を禁止し、解析中のstate不変・保存書込0回を検証した。
- ブラウザでは隔離された一時プロファイル・ローカルoriginを使用し、仮の既存取引・IndexedDB・LocalStorageがOCRと入力反映で変わらないことを確認した。
- 学習辞書は、原本確認後に反映する既存フローだけで更新する。既存学習済み商品が残ることも確認した。
- main・公開中のGitHub Pages・リリース番号・Service Workerキャッシュは変更しない。
- 作業領域に別途追加されていたZIPファイルは変更・コミット対象に含めない。

## 残存する制約

1. Android実機の処理時間・ピークメモリ・カメラ・キーボード・戻る操作は引き続き未検証。
2. 実画像→文字認識の正解率は未測定。今回の改善は再現したテキスト解析・候補正規化に対するもの。
3. 不鮮明な商品名は原本照合が必要。商品名断片がないレシートへ価格だけから商品を追加しない。
4. オーケーの101円が通常抽出で欠ける既存の高速判定例は引き続き未完了扱いとする。通常解析での復元は維持し、今回の変更で高速完了の条件を緩めない。
5. 今回確認していない店舗・表記へ例外を広げない。新しい実例が得られたらfixtureと負例を先に追加する。

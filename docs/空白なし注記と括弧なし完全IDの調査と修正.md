## 再現した問題

第38段階は、価格項目間の「商品／単品」と括弧なし完全IDの間に水平空白を要求していた。次のように明示ラベルと文字種で境界を区切れ、他の根拠もそろっている入力まで保留していた。

```text

0100)

(明細ID 000100) 値引
¥100
緑茶 (明細ID 00
0200)

2200083271771 ¥1,000
(明細ID 000200) 値引
¥200
小計 3点 ¥1700
合計 ¥1700
楽天ペイ ¥1700
```

注記行全体は「商品」＋明示ラベル「明細ID」＋連続した数字IDだけである。IDは行末で終わり、同じ認識元の元の折り返し商品IDと、独立した完全な個別値引参照IDにゼロの桁数まで一致する。逆順の `明細ID000200単品` も、数字の終端と固定した注記語で区切れる。単価500円・商品計1000円によって数量2も独立に確認できるが、基準版では空白必須という条件で採用できなかった。

## 修正と安全条件

`receiptQuantityScopeMarker` の行全体に一致する2つの書式で、注記語と括弧なしIDの間の水平空白を任意にした。空白の有無を除く文字列の推測・修復・部分一致は追加していない。

1. 商品/単品の固定語 → 明示された `明細ID` ラベル → 先頭ゼロ付き数字ID → 行末。
2. 明示された `明細ID` ラベル → 先頭ゼロ付き数字ID → 商品/単品の固定語 → 行末。

注記語自体の対応した括弧、任意コロン、水平空白、既存NFKCによる全角表記を扱う。IDは正の値を示す先頭ゼロ付き連続数字2〜6桁だけで、ラベル・数字・注記語の組を行全体で確認する。価格・数量・商品コードの数字列からIDを作らず、IDの数字を金額や数量として代用しない。

`商品単品明細ID000200`、`明細ID000200商品税込`、長過ぎる数字列、余分なID・数字・価格、ラベルの誤認文字、壊れた括弧などは採用しない。自由文を分割して都合のよい語やIDだけを取り出さない。

第37・38段階の次の条件は維持する。

- 対象は、先頭ゼロ付き数字IDが折り返された、数量の印字がない商品だけ。同じ認識元の元の折り返しID・注記ID・元から完全な独立した個別値引参照IDを、ゼロの桁数まで一致させる。
- 同じ正規化IDの元の完全な出現は、注記1件と独立した値引参照1件の計2件だけを必要とする。注記・商品・参照の重複を照合の補強にせず、復元結果や別の認識元・単独の注記画像からIDを借用しない。
- 注記は、元の商品ID直後の単価・コード付き商品計の間に1行だけ。商品IDや値引参照との境界、別の注記・空行・価格行を読み飛ばさない。注記のIDだけを値引額終端の証拠にしない。
- 元の10〜14桁の数字コード・明示された限定単価書式・金額上限を維持し、商品計÷単価が1〜99の整数で厳密一致するときだけ数量を検証する。印字数量を上書きせず、数量1の既定値・点数・総額・辞書から不足情報を補わない。
- 裸の値引額の局所的な円単位、IDと金額/数量/単価/コードの衝突、税・数量・会計・認識元間の矛盾、末尾の証拠を取り消した場合の依存する前の判定の取り消しも維持する。
- 書き換えは解析用コピーだけ。原文の空白なしの注記・ID・ゼロ・改行・価格順序と呼出元オブジェクトを保持し、一時根拠を保存しない。新しい保存項目やOCR呼び出しは追加しない。

## 残存条件と保護範囲

- 行全体を固定した注記語・明示IDラベル・数字列として区切れない場合や、追加の価格条件を含む場合は保留する。IDなし注記やラベルのない数字列を自動対応へ拡張していない。
- 元から完全な個別値引参照・価格/数量の独立した根拠が不足する場合、重複や矛盾がある場合も手動確認を残す。
- 実店舗の原画像・位置情報・認識率、Android実機のカメラ・速度・メモリ・操作性は未検証。性能同等性回帰は実機速度の測定ではない。
- app.js、保存処理・キー、schemaVersion 12、学習辞書、Service Worker、公開バージョンは変更しない。main・公開中のGitHub Pages・無関係なZIPは変更対象外。

# 空白分断された境界記号と括弧なし完全IDの調査と修正（第42段階）

日付: 2026-11-09 / ブランチ: `codex/receipt-ocr-improvement`
基準: `3958b0d55b08a542df5fd0c7cbb1f049b4d9cc02`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで検証した。実画像・実店舗書式・Android実機からの再現ではない。テスト用の商品・コード・金額を学習辞書へ追加しない。

## 再現した問題

第41段階は、価格項目間の「商品／単品」と括弧なし完全IDの境界にある連続したコロン/ハイフンを扱ったが、記号列の途中のスペース・タブは許容していなかった。次の入力では行全体と元のID・数量・会計を照合できても保留していた。

```text
緑茶 (明細ID 00
0100)
2200083271771 1 ¥1,000
(明細ID 000100) 値引
¥100
緑茶 (明細ID 00
0200)
単価 ¥500
商品: :明細ID000200
2200083271771 ¥1,000
(明細ID 000200) 値引
¥200
小計 3点 ¥1700
合計 ¥1700
楽天ペイ ¥1700
```

スペースは境界のコロン同士の間にあるだけで、IDの数字列や価格の内部ではない。同じ認識元の元の折り返し商品ID・注記ID・独立した完全な個別値引参照IDは、ゼロの桁数まで一致する。単価500円・商品計1000円から数量2も独立に確認できるが、基準版は記号列の分断を理由に採用できなかった。ハイフン・混在記号・タブでも同様だった。

## 修正と安全条件

`receiptQuantityScopeMarker` の括弧なしID用の2つの書式で、境界のコロン/ハイフンそれぞれの後ろにスペース・タブを許容するようにした。対象は1行内の水平空白だけで、汎用的な空白削除・行結合・ID修復は追加していない。

1. 商品/単品の固定語 → コロン/ハイフンと水平空白の境界列（省略可） → 明示された `明細ID` ラベル → 先頭ゼロ付き数字ID → 行末。
2. 明示された `明細ID` ラベル → 先頭ゼロ付き数字ID → コロン/ハイフンと水平空白の境界列（省略可） → 商品/単品の固定語 → 行末。

記号列の同種/混在、対応する括弧で囲まれた注記語、既存NFKCでASCIIへ変換される全角記号・空白等を扱う。変更した位置は注記語とラベル付きIDの境界だけで、IDの数字やIDラベル内部へ広げない。例えば `商品: :明細ID: :000200` や、ID内部の `000 200` / `000 -200` は保留する。

改行・CR・縦タブ・改ページ・ゼロ幅文字等は水平空白として扱わず、複数行の注記を結合しない。数字・通貨・追加条件が境界に混在する場合も採用しない。数学のマイナス `−`、ダッシュ `—`、未知の区切りを推測変換する処理は追加していない。

第37〜41段階の次の条件は維持する。

- 対象は、先頭ゼロ付き数字IDが折り返された、数量の印字がない商品だけ。同じ認識元の元の折り返しID・注記ID・元から完全な独立した個別値引参照IDを、ゼロの桁数まで一致させる。
- 同じ正規化IDの元の完全な出現は、注記1件と独立した値引参照1件の計2件だけを必要とする。注記・商品・参照の重複を照合の補強にしない。復元結果や別の認識元・単独の注記画像からIDを借用しない。
- 注記は元の商品ID直後の単価・コード付き商品計の間に1行だけ。商品IDや値引参照との境界、別の注記・空行・価格行を読み飛ばさない。注記IDだけを値引額終端の証拠にしない。
- IDは正の値を示す先頭ゼロ付き連続数字2〜6桁のみ。ID内部の空白・記号を削除したり数字を補修したりしない。
- 元の10〜14桁の数字コード・限定した明示単価書式・金額上限を維持し、商品計÷単価が1〜99の整数で厳密一致するときだけ数量を検証する。印字数量の上書きや、数量1の既定値・点数・総額・辞書からの不足補完は行わない。
- 裸の値引額の局所的な円単位、IDと金額/数量/単価/コードの衝突、税・数量・会計・認識元間の矛盾、末尾の証拠が失われた場合の依存する前の判定の取り消しも維持する。
- 書き換えは解析用コピーだけ。原文のスペース・タブ・記号・ID・ゼロ・改行・価格順序と呼出元オブジェクトを保持し、一時根拠を保存しない。新しい保存項目やOCR呼び出しは追加しない。

## 残存条件と保護範囲

- 改行や未知制御文字を含む場合、ID内部の空白・記号、数字・価格条件が混在する場合は保留する。空白・記号を一括削除してIDや金額を補修する処理は追加していない。
- 元から完全な個別値引参照・価格/数量の独立した根拠が不足する場合、重複や矛盾がある場合も手動確認を残す。
- ID内部に空白がある今回のヤオコー形式の模擬OCRでは、「商品名要確認」「商品」「単価」という低信頼の未確定候補が表示される既存挙動が残る。候補を正しい明細として扱う根拠は不足するため、自動確定・明細ID付与・値引分割はされず、手動確認を必要とする。候補品質の改善は今回実施していない。
- 実店舗の原画像・位置情報・認識率、Android実機のカメラ・速度・メモリ・操作性は未検証。性能同等性回帰は実機速度の測定ではない。
- app.js、保存処理・キー、schemaVersion 12、学習辞書、Service Worker、公開バージョンは変更しない。main・公開中のGitHub Pages・無関係なZIPは変更対象外。

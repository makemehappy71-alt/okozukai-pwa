# 継続記号のない複数行明細IDの調査と修正（第18段階）

日付: 2026-11-07 / ブランチ: `codex/receipt-ocr-improvement`
基準: `167357ca127269c9a8e1bab8527eb6a9a401ce83`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで、行末に継続記号がないIDと値引帰属を再検証した。新しい実画像・実店舗の印字形式は検証していない。商品名・コード・価格の組合せはテスト用で、辞書へ追加していない。

## 再現した問題

同じ認識元に閉じた括弧と独立した完全なIDがあり、商品と値引参照が一意に照合できても、基準版は行末の `-`・`_` がないことを理由に復元を保留する。商品側と値引参照側の両方で再現した。

```text
緑茶 (明細ID A
101)
2200083271771 1 ¥1,000
…
(明細ID A101) 値引 ¥100
```

この例は完全なA101が別に印字される場合に限る。A101とA 101の両方が読める場合や、完全なIDがない場合は、改行の意味を判断できないため保留を維持する。

## 見直した復元条件

第17段階の復元条件から、行末の継続記号を必須とする制約だけを見直した。以下の条件は引き続き必要とする。

1. `明細ID` と明記され、値部分またはラベルと値全体が、対応する1組の括弧で閉じる。
2. 2〜3行に収まり、断片は英数字と既存の `-`・`_` からなる。タブ・空行・別のラベル・価格・税等を挟まない。
3. 断片をそのまま連ねた綴りが、同じ認識元にある独立した完全なIDと一致する。
4. 商品側の折り返しには、一意の完全な個別値引参照がある。参照側の折り返しには、一意の完全なIDを持つ、商品名・数量・価格が読める商品明細がある。
5. 空白を含む別IDとの競合、重複ID、複数候補がない。実際の認識記録がある場合は、その記録内で根拠が成立する。
6. 復元後も明細が一意で、印字点数・小計・税額・値引・支払額の検証を通る。

途中行も継続記号なしで扱えるため、A / 10 / 1の3行からA101を照合するケースも対象にした。完全な印字に存在しない文字・記号・空白を補完せず、ケースやO/0等も訂正しない。
数字だけのIDでも、結合した綴りが既存の検証と完全な印字に一致する場合だけ対象にする。結合した断片から先頭ゼロを取り去らなければ一致しないケースは採用しない。

継続記号のない行末に印字空白が残る場合は、その空白を削除してよい根拠がないため保留にする。最初の行・途中行の両方にこの保護を追加した。
継続行のタブも判定前に保持し、タブを空白へ変えて復元可能にしない。元のID中の記号は、そのまま保持する。

## 保留・原文・保存の保護

- 括弧だけ、前後の商品名・金額が近いだけでは復元しない。
- 両側とも折り返されて完全な印字がない場合、別のOCRパスだけに完全なIDがある場合、結合テキストだけで根拠が成立する場合は保留にする。
- 任意の番号行、会計後のフッター、学習辞書を完全な商品・値引参照の代わりにしない。
- A101とA 101が両方ある場合や、完全な印字がA 101だけの場合は、空白の有無を推測しない。
- 商品名が読めないコードだけの明細、会計不足、未知の参照、矛盾や重複があれば自動確認・自動分割を停止する。

解析用のコピーだけを復元し、復元前の正規化済みOCR原文と入力オブジェクトを保持する。確認画面では照合案内と原文を表示し、原本の値引先の確認を促す。保存用の分割計画・取引・学習辞書には、IDや復元情報の新項目を追加しない。

条件の見直しに伴い、従来テストは次のように更新した。

- 第16段階の45件では、LF・CR・CRLFの参照側について、前置参照・後置参照・単一参照の計9件を、完全な商品IDがある場合の復元確認へ変更した。商品側の分断で完全な参照がないケース、タブ・空行は保留のまま。
- 学習辞書の迂回防止ケースは、完全な商品IDが見つからないA＋CR＋999へ入力を変更し、保留と保存書込0回の期待を維持した。
- 第17段階の61件では、A-1 / 01とA- / 10 / 1の2件を、完全なA-101の印字がある復元確認へ変更した。計11件の期待動作更新であり、既存スイートの件数は維持した。
- ブラウザの既存CR分断参照1ケースも、完全な商品IDで照合できることを確認するケースへ変更した。

新規回帰は、商品側・参照側、各括弧、値部分の括弧、前置・商品後・同一行、3断片、数字ID、全角、LF/CRLF/CR、単一値引、税配分、原文・入力オブジェクト保持を検証した。
完全な印字の欠落、両側の折り返し、別パスだけの根拠、空白付きIDの競合、印字空白・タブ・空行・4行以上・不正な括弧・綴り違い・重複・会計不足、フッターや学習辞書による迂回も検証した。
模擬workerの3ケースで、商品側・参照側の条件付き復元と、タブ付き継続行の保留、終了1回・保存書込0回を確認した。仮の既存取引・辞書・schemaVersion 12も維持した。

ブラウザには412pxの3ケースを追加した。

1. 商品側のA / 101とB / 102を完全な値引参照で照合し、値引100円/200円・支払900円/800円で分割する。
2. 値引参照側のA / 101とB / 102を完全な商品IDで照合し、同じ結果で確認・分割する。
3. A101とA 101が同時に読める場合は保留・警告とし、商品名の手入力後も分割計画を作らない。

照合案内と折り返しを残す原文表示、保存用計画にIDを追加しないことも検証した。従来の360px・412px、各ID形式・値引・値下・税配分と実canvas画素一致も確認した。隔離ブラウザの仮の取引・辞書・IndexedDB/LocalStorageを使用し、実データは開いていない。OCRは模擬である。

## 残存問題と保護範囲

- schemaVersion 12、app.js、保存処理・キー、学習辞書、Service Worker、公開バージョンを維持する。
- 指定作業ブランチだけへ反映し、mainと公開中のGitHub Pagesは変更しない。無関係なZIPとテスト成果物はコミットしない。
- 4行以上、タブ、内部空白の復元、印字空白の削除、欠けた文字・記号の補完、同じIDの複数の折り返し等は引き続き手動確認が必要。
- 完全なIDと括弧が読めることが前提であり、任意の改行を削除する機能ではない。
- 実画像の折り返し位置・座標、実店舗の書式、ID認識率、Android実機の速度・カメラ・メモリ・操作性は未検証。

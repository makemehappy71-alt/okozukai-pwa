## 安全性と作業範囲

- 指定ブランチを新しいローカル作業領域へ取得。main・GitHub Pagesには書き込まない。初回監査・修正は未pushで実施し、追加依頼に基づき最終レビュー合格後に作業ブランチだけをコミット・pushする。公開は行わない。
- schemaVersion 12、DB名、LocalStorageキー、学習辞書形式を維持する。保存・migration処理は今回変更しない。
- Node VMで起動IIFEを実行せず、メモリ上の仮データとLocalStorage代替を使用する。IndexedDB接続を禁止し、保存書込がないこととstate不変を検証する。
- 西友・ヤオコー・MEGAドン・キホーテの既存回帰を含めて比較する。確認できない商品名を追加・自動確定しない。
- 実機レシートの画像やユーザーの家計簿データを新規取得・保存しない。

## 基準テスト

`node tests/run.cjs`（Node標準ライブラリのみ）:

- 家計簿: 61/61 合格。
- OCR: 327/337 合格、10件失敗。
- state復元・解析時不変、保存書込なしを確認。
- 画像→文字の認識精度を測るテストではなく、保存済みOCRテキスト・座標fixtureからの解析テスト。

失敗名と原因調査:

追加確認事項:

- 数量の代替解析に `s*` があり、空白用の `\s*` になっていない。単価ラベルの選択順も検証する。
- GUの商品別・全体カテゴリで「シャツ」が「Tシャツ」より先に評価される。
- 店舗OCRの省略条件が別の固定ブランド一覧を持ち、ヤオコー・MEGA等の既知店舗でも再OCRが走る。
- OCRライブラリ読込失敗後のPromise・scriptが残り、再試行できない経路がある。ネットワーク失敗を模擬して再検証する。
- 画像領域を複数の拡大canvasとして先に作るためメモリ負荷がある。実測・画像の根拠なしに解像度やpassを一律削減しない。
- 商品部分集合探索は最大18候補で指数時間。性能測定と結果同等性を確認してから対応を判断する。
- 起動時にloadState/persistが走る。実データのある本番originを監査用に開かない。
- 最終監査で動作テストによる選択月・分析期間の変更残りを再現した。テストの状態復元を追加の安全性改善に含める（結果文書参照）。

## 実施順序と受入条件

1. 保存から隔離した再実行可能なテスト基盤を作成し、既存失敗を固定する。
2. 共通の数量・商品合意・短い商品名・税額解析を小さく修正し、負例を追加する。
3. カテゴリの優先順を修正し、既知店舗判定を共通化する。店舗の確認済み商品辞書は維持する。
4. OCR失敗→再試行、worker終了処理、既知店舗のpass数を模擬テストする。
5. ローカルの隔離ブラウザでモバイル画面・確認操作を検証する。Android実機の速度測定と区別する。
6. 改善前後のテスト数・合格数・残存問題・変更ファイルと再現コマンドを結果文書へ記録する。

画像OCR、Android実機での初回言語データ読込・処理時間・メモリ・カメラ入力は、実機接続と同一画像の反復測定が必要。未実施のものを検証済みとして扱わない。

# 複数行に折り返された明細IDの安全な復元と値引帰属（第17段階）

日付: 2026-11-07 / ブランチ: `codex/receipt-ocr-improvement`
基準: `e013f843428e8dc2a3e7628a4e465cfc08025c1c`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで、括弧と前後の完全な印字から折り返しIDを照合できる条件を調査した。新しい実画像や実店舗の折り返し形式は検証していない。商品名・コード・価格の対応は仮の例であり、辞書へ追加していない。

## 再現した問題

基準版では、次のように括弧が対応し、同じ認識元に完全なIDと値引参照が印字されていても、折り返しIDは保留になる。商品側が折り返される場合と、値引参照側が折り返される場合の両方を再現した。

```text
緑茶 (明細ID A-
101)
2200083271771 1 ¥1,000
…
(明細ID A-101) 値引 ¥100
```

括弧が閉じるだけ、商品名・金額が近いだけでは、改行を消してよい根拠にならない。追加の完全な印字があるケースに限定して復元する。

## 復元に必要な条件

| 条件 | 判定 |
| --- | --- |
| ラベル | `明細ID` と明記されている |
| 外側の境界 | ラベルと値全体、または値部分が、対応する1組の丸括弧・角括弧・【】で閉じる |
| 行数 | 2〜3行に収まる |
| 継続の根拠 | 最終行以外のID断片は、印字された `-` または `_` で終わる |
| 断片 | 英数字と `-`・`_` だけ。継続行に空行・タブ・価格・税・別ラベル等を挟まない |
| 結合後 | 既存のID検証を満たし、記号込みで16文字以内。文字や記号を補完・訂正しない |
| 独立した完全な印字 | 同じ認識元に、同じIDが1行で完全に印字されている |
| 商品側の折り返し | 完全なIDを持つ明示的な個別値引参照が一意に存在する |
| 値引参照側の折り返し | 完全なIDを持つ、商品名・数量・価格が読める商品明細が一意に存在する |
| 競合 | 空白を含む別IDでも同じ断片に対応する場合や、同じIDが複数明細に対応する場合は復元しない |

例えば `A-` と `101` を結合した候補は、独立して印字された `A-101` と一致する必要がある。`A- 101` という別の完全な印字も存在する場合は、空白の有無を判断できないため保留にする。
大文字・小文字、O/0、I/1、先頭ゼロ、記号を変更しない。全角互換表記は従来のNFKCで照合する。
完全なIDが別のOCRパスにしかない場合、任意の番号行・会員情報・値引合計・会計後のフッターにしかない場合は、復元の根拠に使わない。

実際の認識記録（全体・分割・商品領域）が入力にある場合は、その記録内で照合できたIDだけを復元対象にする。複数パスを結合した文字列から、新しい「同じ認識元」の根拠を作らない。認識記録のない単一文字列入力は、その文字列を1認識元として扱う。

## 復元後の検証と保留

復元候補を解析用のコピーへ適用し、IDごとに、読める商品名・数量・価格を持つ明細が一意に存在するか再検証する。コードだけで商品名が読めないもの、不正なID対応、重複した折り返し候補は採用しない。
その後も既存の商品コード（コードなしなら商品名）・数量・元価格・印字点数・小計・税額・支払額の検証を通す。会計不一致やOCR間の値引割当の矛盾があれば、自動確認・商品別の自動分割は止める。

次のような分断は、引き続き復元しない。

```text
A
101          ← 継続を示す記号がない

A-1
01           ← 行末に継続記号がない

A-
101          ← 括弧や、同じ認識元の完全な印字がなければ保留
```

前処理では、折り返し候補がある認識元の継続行の空白・タブも判定まで保持する。タブを空白に変えて復元可能な行へ昇格させない。
入力オブジェクトを変更せず、復元前の正規化済みOCR原文を `rawText` と診断表示へ保持する。復元したID数は解析中だけに保持する。帰属が確認できた場合は、完全な印字と照合した旨を確認画面へ表示し、原本の値引先の確認を促す。
保存用の分割計画・取引・学習辞書に、IDや復元情報の新項目は追加しない。

追加回帰では、商品側・値引参照側、値部分の括弧、前置・商品後・同一行、前後の値引参照、3行のID、数字区間のID、全角、LF/CRLF/CR、片方だけの値引、税配分、OCR配置違い、原文・入力オブジェクトの保持を検証した。
完全な印字の欠落、両側の折り返し、別パスだけの根拠、結合テキストによる根拠の捏造防止、空白付きIDの競合、タブ・空行・4行以上・不正な括弧・税行・コメント・重複・異なる綴り、会計不足、学習辞書の迂回防止も検証した。
模擬workerの3ケースで、商品側と参照側は条件付きで復元し、タブのある継続行は保留すること、終了1回・保存書込0回を確認した。仮の既存取引・辞書とschemaVersion 12も維持した。

ブラウザには412pxの3ケースを追加した。

1. 商品側の折り返しを完全な値引参照で照合し、A-101/B_102を値引100円/200円・支払900円/800円の分割計画に渡す。
2. 値引参照側の折り返しを完全な商品IDで照合し、同じ結果で確認・分割する。
3. A-101とA- 101の両方が印字される場合は保留・警告とし、商品名の手入力後も分割計画を作らない。

照合の案内表示、折り返しを残す原文表示、保存用計画にIDを追加しないことも確認した。従来の360px・412px、各ID形式・値引・値下・税配分と実canvas画素一致も合格した。隔離ブラウザの仮の取引・辞書・IndexedDB/LocalStorageを保持した。OCRは模擬である。

## 保護範囲と残存問題

- schemaVersion 12、app.js、保存処理・キー、学習辞書、Service Worker、公開バージョンを変更しない。実データを開かず、仮データだけを使う。
- 指定作業ブランチだけへ反映し、mainと公開中のGitHub Pagesは変更しない。無関係なZIPとテスト成果物は対象外。
- 任意の複数行IDを復元する機能ではない。継続記号・対応する括弧・同じ認識元の完全な印字のいずれかが欠ければ保留する。
- 内部空白の復元、タブ、4行以上、同じIDの複数の折り返し、数字だけで区切りのない折り返し、文字・記号の誤読訂正は未対応。
- 実画像の座標・印字の折返し位置を根拠にする検証は行っていない。実店舗の書式、認識率、Android実機の速度・カメラ・メモリ・操作性は未検証。

# 連続記号付き注記と括弧なし完全IDの調査と修正（第41段階）

## 再現した問題

第40段階は、価格項目間の「商品／単品」と括弧なし完全IDの境界にあるコロン/ハイフンを1個に限定していた。次のように境界に連続した記号列があっても、行全体と元のID・数量・会計を一意に照合できる入力まで保留していた。

```text
緑茶 (明細ID 00
0100)
2200083271771 1 ¥1,000
(明細ID 000100) 値引
¥100
緑茶 (明細ID 00
0200)
単価 ¥500
商品::明細ID000200
2200083271771 ¥1,000
(明細ID 000200) 値引
¥200
小計 3点 ¥1700
合計 ¥1700
楽天ペイ ¥1700
```

同じ認識元の元の折り返し商品ID・注記ID・独立した完全な個別値引参照IDは、先頭ゼロの桁数まで一致する。境界の記号列は「商品」と明示ラベル「明細ID」の間にあるだけで、ID自体は数字のみ。単価500円・商品計1000円から数量2も厳密に確認できるが、基準版では境界記号の個数を理由に採用できなかった。

逆順の `明細ID000200---単品` や `商品:-明細ID000200` のような混在も調べた。次に来るのは固定した語または明示IDラベルであり、数字や通貨ではない。したがって、行全体が限定構文に一致する場合には、ID内の記号・範囲表現・負の金額から区別できる。

## 修正と安全条件

`receiptQuantityScopeMarker` の括弧なしID用の2つの書式で、注記語とラベル付き完全IDの境界を、連続したASCII `:` / `-` の列として読むようにした。同種の反復と混在を扱うが、記号列は連続していなければならない。記号列の前後にある水平空白は従来どおり許容する。

1. 商品/単品の固定語 → 連続した境界記号列（省略可） → 明示された `明細ID` ラベル → 先頭ゼロ付き数字ID → 行末。
2. 明示された `明細ID` ラベル → 先頭ゼロ付き数字ID → 連続した境界記号列（省略可） → 商品/単品の固定語 → 行末。

対応する括弧で囲まれた注記語、既存NFKCでASCIIへ変換される全角のコロン/ハイフン等も扱う。記号列を読む位置は注記語とラベル付きIDの境界だけで、IDの数字やIDラベル内部へ広げない。例えば `商品::明細ID::000200` は、ラベルと数字の間のコロンが従来の条件に一致しないため保留する。

`商品: -明細ID000200` のように記号列が空白で分断される例、ID内部の `000--200`、`明細ID000200--01::商品` のような数字が続く例、通貨・条件文・未知の区切りや制御文字が混在する例をまとめて除去しない。数学のマイナス `−` やダッシュ `—` をASCIIハイフンへ推測変換する処理も追加しない。

第37〜40段階の次の条件は維持する。

- 対象は、先頭ゼロ付き数字IDが折り返された、数量の印字がない商品だけ。同じ認識元の元の折り返しID・注記ID・元から完全な独立した個別値引参照IDを、ゼロの桁数まで一致させる。
- 同じ正規化IDの元の完全な出現は、注記1件と独立した値引参照1件の計2件だけを必要とする。注記・商品・参照の重複を照合の補強にせず、復元結果や別の認識元・単独の注記画像からIDを借用しない。
- 注記は元の商品ID直後の単価・コード付き商品計の間に1行だけ。商品IDや値引参照との境界、別の注記・空行・価格行を読み飛ばさない。注記IDだけを値引額終端の証拠にしない。
- IDは正の値を示す先頭ゼロ付き連続数字2〜6桁のみ。数字を修復したり内部の記号を削除したりしない。
- 元の10〜14桁の数字コード・限定した明示単価書式・金額上限を維持し、商品計÷単価が1〜99の整数で厳密一致するときだけ数量を検証する。印字数量の上書きや、数量1の既定値・点数・総額・辞書からの不足補完は行わない。
- 裸の値引額の局所的な円単位、IDと金額/数量/単価/コードの衝突、税・数量・会計・認識元間の矛盾、末尾の証拠が失われた場合の依存する前の判定の取り消しも維持する。
- 書き換えは解析用コピーだけ。原文の連続記号・ID・ゼロ・空白・改行・価格順序と呼出元オブジェクトを保持し、一時根拠を保存しない。新しい保存項目やOCR呼び出しは追加しない。

- 記号列がID内部にある場合、途中に空白・数字・未知の文字がある場合、追加の価格条件がある場合は保留する。記号を一括削除してIDや金額を補修する処理は追加していない。

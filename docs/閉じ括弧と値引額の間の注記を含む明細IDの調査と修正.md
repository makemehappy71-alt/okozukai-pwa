# 閉じ括弧と値引額の間の注記を含む明細IDの調査と修正（第23段階）

日付: 2026-11-08 / ブランチ: `codex/receipt-ocr-improvement`
基準: `ef10ffad3d2bdda1e7c6edddebe93c08a9f90590`

人工OCR文字列・模擬worker・隔離ブラウザの仮データで再検証した。実画像・実店舗書式・Android実機での再現ではない。テストの商品名・コード・金額は学習辞書へ追加しない。

## 再現した問題と対応範囲

基準版は、閉じ括弧と明示された値引額が同じ行なら復元できるが、その間に括弧付きの「単品」「商品」があると保留する。通常の1行IDでも、ID直後に別の括弧があるため参照として認めない。同じ認識元に完全な商品IDが一意に存在し、点数・小計・値引・支払額が整合する場合にも再現した。

```text
緑茶 (明細ID A101)
2200083271771 1 ¥1,000
…
(明細ID A101
) (単品) 値引 ¥100
```

注記を一律に除去する処理は追加しない。「対象外」「次回用」などを除去すると値引の意味を変えてしまう。今回は、既存の「商品値引」「単品値引」と同じ個別商品の範囲を明示する、対応する1組の括弧に入った「商品」「単品」だけを扱う。実店舗の注記一般が無害だと判断したものではない。

## 修正と安全条件

`receiptDiscountScopeNote` を共通処理として追加した。対応する括弧内の語が「商品」「単品」と完全一致し、その直後に既存の値引・割引・値引額・割引額・値下額・値下げ額と単一の整数金額がある場合だけ、解析用表記を「商品値引」「単品値引」等へ変換する。スペース・タブ、通貨記号、コロン、負号、円は限定した金額書式内で扱う。全角の正規化は従来のNFKCを使う。

通常の1行IDと折り返しIDが共通処理を使う。1行IDでは、ID自体にも対応する括弧がある場合だけ、直後の括弧の例外を認める。括弧のないID、二重括弧、不一致括弧、複数の注記、追加の条件・ID・金額・率、未知の注記には広げない。

折り返しIDでは閉じ括弧行の注記を限定して解析し、既存の値引参照の復元処理に渡す。以下の既存条件を維持する。

- 同じ認識元に、折り返しのない完全なIDを持つ商品名・数量・価格付き明細が一意に存在する。別OCRパス・結合テキスト・任意のIDラベル・学習辞書を代わりの根拠にしない。
- 空白付きの別IDとの競合や重複がなく、復元後も対象が一意である。両側の折り返しを自己証明させない。
- IDは16文字以内、最大16個の非空断片と直後の閉じ括弧行まで。空行・別情報を読み飛ばさず、ID内部のタブ・空白・文字・記号を補修しない。
- 印字点数・小計・税・値引・支払額とOCRパス間の割当整合性を検証する。注記を解析できるだけで自動確定しない。

通常の1行IDでも、別の認識元にだけ商品がある場合や、結合テキストだけに対応がある場合は確定しないことを検証した。完全な注記付き参照による複数値引の合算と、折り返し商品側への帰属も確認した。同じIDの折り返し参照が複数ある場合は、既存の重複候補の保留条件を維持する。

元の正規化済みOCR原文・注記・タブ・改行と呼出元オブジェクトは保持する。注記の解析表記は保存用計画・取引・学習辞書の新項目として追加しない。

## 残存条件・保護範囲

- 対応する括弧付きの「商品」「単品」以外の注記は原則保留する。自由記述を削除したり、注記の意味を推定したりしない。
- 注記自体・値引額が別行の場合、価格と区別できない表記、複数条件・複数注記、ID内部の欠損は新しい対象に含めない。
- 同じ認識元の完全なID・一意な対応・会計の整合性が欠ける場合は手動確認を残す。
- 実画像の印字位置・店舗書式・認識率、Android実機の速度・カメラ・メモリ・操作性は未検証。
- app.js、schemaVersion 12、保存処理・キー、学習辞書、Service Worker、公開バージョンは変更しない。実データは開かず、仮データだけを使う。
- 指定作業ブランチだけへ反映する。main・公開中のGitHub Pages・無関係なZIP・Git管理対象外のテスト成果物は変更対象外。
